# CVD-2D 工艺数据标准 (CVD-2D Process Data Standard) — v2.0（草案 / DRAFT）

> 状态：**DRAFT**，供内部审阅，尚未冻结。
> 规范版本：`2.0.0`（草案）。对应目标数据载荷 `schema_version = cvd_v2`（**规划中、尚未实现**）。

> 适用范围：化学气相沉积（CVD）法生长二维材料的**工艺参数 → 客观结果（含失败）** 数据；含物理气相沉积（PVD）延后 profile。
> **权威字段字典**：机读、逐字段的权威清单是 [`字段草案-v3.xlsx`](字段草案-v3.xlsx)。本文是**人读规范 + 规则书 + 设计依据 + 词表 + 治理**；字段级明细以 xlsx 为准（§8 只给模块级导航，避免第二套真相漂移）。

## 0. 这份文档是什么 / 不是什么

- **是**：一本带版本号的"规则书 + 设计依据 + 受控词表 + 治理约定"，配套 `字段草案-v3.xlsx`（字段字典）。任何机构照它 + xlsx 产数据，数据就互相兼容、可合并、可喂给模型。
- **不是**：不是软件文档，也不绑定本系统某次实现。本系统（FastAPI + React）是本标准的**参考实现**之一，而非标准本身。

设计目标对齐国际科研数据通行框架 **FAIR**（可发现 / 可访问 / 可互操作 / 可复用）。其中最难的 **可复用（Reusable）** 为首要目标——它依赖"丰富且一致的元数据"，正是本标准的核心。

**v1 → v2 的定位转变**（导师 2026-06-11 组会批评后重构）：
- v1 把工程能力（建站、版本管理、导出）当卖点；v2 降其权重。
- v2 的核心主张 = **"面向气固多相 CVD 的最小可复现元数据标准"本身**：每个字段有机理/文献依据、经与制备同学逐条评审、有国际对标（NOMAD/GEMD/ESCALATE/2DCC）、有失败溯源验证路径。

## 1. 设计原则

### 1.1 六条基本原则（P1–P6）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **失败即数据（True Negative）** | 失败 / 中断的炉次**必须**作为正式记录保存，不得当草稿丢弃。公开材料库普遍缺"尝试过且失败"的真负样本，这是本标准最大价值。**注意 v2 的实现方式变化见 §7**：不在录入端贴"成/败"标签，而是留存客观事实。 |
| P2 | **`null` ≠ `0`** | 空值 = 未测量 / 未记录；显式 `0` = 测得为零。表单与导入器**不得**把空白强制转成 0。 |
| P3 | **设定值 vs 实测值** | 过程量（温度/流量/压力）区分**设定值**与**实测值**；数值须能标出来源（设定/实测/估计）。温度字段 v2 落为「设定温度 + 实测温度」两层（删除 v1 草案曾有的"估算衬底真温"）。 |
| P4 | **单位显式且权威** | 每个数值字段的单位由字段字典权威定义，随导出输出，不靠字段名后缀隐含约定。SI 存储、习惯单位显示。流量 sccm 须绑标准状态。 |
| P5 | **单一权威 + 防漂移** | 字段字典（`字段草案-v3.xlsx`）是对外发布规范层；运行时校验由 Pydantic 承担；两者用一致性测试强制对齐，杜绝"多套真相"漂移（见 §6）。 |
| P6 | **对接而非重造** | 复用 FAIR / OPTIMADE / DataCite / EMMO / CHMO 既有生态；只对"CVD-2D 工艺 + 失败"这一真正空白自建词表。 |

### 1.2 字段准入五判据（元数据"到底"的可操作标准）

导师定义：元数据 = 数据已"到底"、不可再分割，价值在溯源失败。每个字段过这五关，过不了的删：

1. **数值化 / 受控**：能量化的必须数值 + 单位；不能量化的用受控词表，**禁止主观形容词**（如删除 v1 的 clean/normal/contaminated 样品环境枚举，改悬浮粒子浓度数值）。
2. **不可再分**：复合概念拆维度（如"蓝宝石单抛C<0001>"→ 材料/抛光/晶向三字段）。
3. **可溯源**：凡涉及实物（化学品/衬底/气瓶/仪器），记录的是**批次/实体引用**而非名字（见 §3 实体引用）。
4. **有依据**：每个字段写得出"为什么记"（机理或文献）——见设计依据文档。
5. **来源明确**：数值能区分设定值 / 实测值 / 估计值（P3）。

## 2. 版本与治理

- **语义化版本** `MAJOR.MINOR.PATCH`：MAJOR = 不兼容的字段删除/语义变更；MINOR = 向后兼容的新增字段/新增词表值；PATCH = 文字/标签修订，不改数据形态。
- 数据载荷携带 `schema_version`。当前线上 `cvd_v1`（↔ 规范 0.1.x）；本 v2 目标 `cvd_v2`（↔ 2.0.x），**尚未实现**。届时提供 `cvd_v1 → cvd_v2` 迁移脚本。
- **受控核心 + 登记扩展**：核心字段集由本规范统一管理；机构特有扩展字段须加机构前缀（参照 OPTIMADE `_provider_`，如 `_pku_chamber_pressure_pa`），不得污染核心命名空间。
- **术语审定**：中文字段名依国标 / 计量规范 / 名词委审定名核证（衬底≠基底、批号≠批次号、环境温湿度≠室内温湿度、吹扫≠洗炉、校准≠标定、晶畴尺寸、覆盖率、随炉冷却/快速冷却、硫属源、悬浮粒子浓度等）。完整对照见设计依据文档 §六。
- **演进治理**：推广期设轻量"标准维护小组"审字段增改；近期以 PI 间轻量协议替代正式委员会（借鉴 CIF/COMCIFS）。

## 3. 数据模型总览

**最小记录单元 = 一个炉次（一炉一行）**，`run_code` 唯一标识。

```
ExperimentRun (run_code 唯一标识)
├── 实验级标量（一等列, 可索引/查询）
│     experiment_time(t0) · synthesis_method · operator · status …
├── 9 个工艺/目标/结果模块（§1–§8，见下）
├── 引用的一等实体（只引用 + 快照冻结，不重复录入）：
│     装置库 Setup · 物料批次库 MaterialLot
├── Samples（样品, 含谱系 parent_sample_id —— 可追溯）
├── FileAssets（原始/派生文件: setup 图 · 表征原始文件 · 导入源表, 留校验和）
└── Versions + Audit（不可变版本快照 + 审计日志 —— 溯源）

Characterization (char_code 唯一标识)   ← 独立表
└── 用 run_code / sample 与 ExperimentRun 关联（"长一批、表征一批"非一一对应，见 §7）
```

**模块清单（与 `字段草案-v3.xlsx` 一一对应）：**

| § | 模块 | 形态 | 说明 |
|---|---|---|---|
| §1 | 基本信息 basic_info | 对象 | 实验时间(t0置首) · 合成方法(顶层CVD/PVD选择器) · 实验人 · 编号 · 环境温湿度 · 悬浮粒子浓度 |
| §1b | 目标产物 target_product | 对象 | 化学式 · 结构类型 · 目标层数 · 体相空间群 · 形态 · 目标性能 · 备注 |
| §2 | 设备与装置 setup | 对象(引用) | 装置库引用 + 壁型 · 温区数 · 炉体方向 · 管材质/尺寸 · **坐标系(全局定死)** · 外场激励 · 炉管/舟履历 |
| §3 | 前驱体 precursors | **数组** `items[]` | 每种一条：名称/化学式 · CAS · **批次引用** · 角色 · 用量(投料) · 处理方式 · 舟坩埚 · 温区/距离 |
| §4 | 衬底 substrates | **数组** `items[]` | 每片一条：材料 · 化学式/取向 · 氧化层厚度(条件) · 粗糙度 · 尺寸/朝向 · 预处理序列 · 温区/距离 |
| §5 | 反应条件 process_steps | **数组**(按阶段) | 每步一套：阶段类型(驱动动态表单) · 温度(设定+实测) · 气体 · 压力体系 · 时长/循环 · 外场参数 |
| §6 | 过程事件 process_events | **数组** | 客观事件：事件/部位 · 发生时刻 · 中止原因 · 描述/附件（见 §7 结果哲学） |
| §7 | 产物表征 + 实测产物 characterization | **独立表** | 表征类型/仪器 · 测试条件 · 原始数据 + 实测产物(检出相/层数/覆盖率/畴尺寸/谱学) |
| §8 | PVD 专用 pvd_profile | 对象(条件) | 合成方法选 PVD 才启用；靶材/靶基距/功率偏压/气氛/时序/沉积速率。**延后实现、先占位** |

### 3.1 一等实体：引用 + 冻结

对标 NOMAD/GEMD 的 Spec-vs-Run 与 ESCALATE 的 Material-vs-InventoryMaterial：

- **装置库 Setup**：一台炉登记一次，实验只引用；引用时**快照冻结**当时的装置定义（含坐标系原点/轴向定义），事后改装置不影响旧记录。
- **物料批次库 MaterialLot**：化学身份层（物质名/CAS/分子式）+ 商业批次层（供应商/货号/**批号/纯度/粒径**/形态/开封/存储/证书）。衬底批次子类 + 氧化层厚度/晶向/抛光；气瓶批次 + 纯度等级。实验中前驱体/衬底**只填批号引用**，纯度粒径自动带出并锁版。

> **注**：MaterialLot / 结构化 Setup / 表征仪器这三张一等实体表目前只有散文定义，**权威字段表待补**（下一轮，见 §11）；`字段草案-v3.xlsx` 当前只覆盖"实验记录"的字段。

### 3.2 记录单元与关联（2026-07-06 拍板）

- **记录最小单元 = 炉次**（`run_code`）；R0 提交校验挂在炉次上。
- **样品（Sample）= 关联主键**：一炉生成 1..n 个样品（v1 已有，含 `parent_sample_id` 谱系）。
- **表征为独立记录**（`char_code`），**外键指向样品**（可回退到 `run_code`）——对应"长一批、表征一批"的真实流程。
- 转移 / 堆垛等后处理，未来作为**挂在样品上的轻量事件**，不改动记录单元。
- 不采用"以样品为全生命周期主线"（2DCC 式平台工程），现阶段课题组 ELN 不背这个复杂度。

## 4. 数值与单位约定

- 单位以字段字典 `unit` 为准（℃ / % / %RH / sccm / mg / Pa / mm / nm / min / W / 个·m⁻³ 等），导出随每个数值输出。
- **`null` ≠ `0`**（P2）。
- **位置/坐标系（全局定死，非逐次可选）**：装置坐标系原点固定、**上游为负、下游为正**，水平与竖直炉一致；逐项只记「温区号 + 距热电偶距离(±, mm)」。坐标系定义在装置库登记一次并随引用冻结。
- 温度 ℃；流量 **sccm（须绑标准状态）**；压力 **Pa**（工作压力 + 压力体系 常压APCVD/低压LPCVD/超高真空）；时间 min；湿度 %RH。
- 尺寸结构化为数值（长×宽[×高]），不用 "5x10" 字符串。
- **未来对接**：单位映射 QUDT / EMMO；合成方法挂 CHMO 本体（CVD=CHMO:0001314 / APCVD=0001316 / LPCVD=0001322 / MOCVD=0001324）。

### 4.1 时序数据的落地（避免塞进 payload_json）

实测时序（炉温热电偶、MFC 采集，可达数万点）**不进 `payload_json`**——否则 GIN 索引膨胀、每次版本快照全量复制 payload 会爆。落地为三层：

1. **原始曲线** → `FileAsset`（csv / parquet + 校验和，机制已有）；
2. **时序通道注册**（轻量表）：量纲 / 单位 / `measurement_type`（set / measured / assumed）/ 相对 t0 偏移 / 关联 `run_code` + 步序；对标 NOMAD 的 TimeSeries 四元组 + measurement_type；
3. **派生标量进 payload**：实际峰温、超调量、保温实测均值、降温速率等——可索引、可比较、可喂模型。

`字段草案-v3.xlsx` 中"实测温度 = 数组(时序)"指的是①②的入口，不是把数组直接写进 payload。

**跨字段校验规则（防冗余矛盾）**：
- `合成方法` 的 APCVD/LPCVD 前缀与 `压力体系` 记录同一事实，**须一致**（合成方法=LPCVD ⇒ 生长段压力体系=低压）；实现上以校验规则强制，或 `合成方法` 只记 CVD/PVD 大类、压力细节交给 `压力体系`。
- `gas_species` 只保留纯气体；v1 的混合枚举（Ar+H2 / air 等）迁移时拆成 components 多行（air → N₂+O₂ 或加标注）。

## 6. 单一权威与防漂移（P5 落地）

字段定义有三处，会漂移：① `字段草案-v3.xlsx`（规范层，对外发布）② Pydantic module payload schema（运行时校验权威）③ `payload_json`（实存数据）。

**收敛方案（v2 目标，随重构落地）：**
- Pydantic 为运行时校验权威（严格、有测试）。
- `字段草案-v3.xlsx` 为对外发布规范层：本规范文档与机读 JSON Schema 均据它生成。
- **一致性测试**：断言"每个 Pydantic 字段都有对应字段定义，且类型/单位/必填/词表一致"，CI 强制，任一处单独改都会红。
- 现系统已有的 regen-drift 测试在 v2 落地时会强制"标准 ↔ 产物"同步。

## 7. 结果模型：客观事实优先（v2 的关键立场，相对 v1 有变）

> **v1 立场**：录入端用 `outcome_category`（success/partial/failed/aborted）+ `failure_mode` 受控词表给炉次贴"成败/失败模式"标签。
> **v2 立场（2026-06-24 决定）**：**不在录入端下成败判断**。分两处只记**客观事实**：
> - **§6 过程事件**：如实记客观事件（气流中断、人工干预、计划结束…），不写成"失败"；中止只记客观原因（`abort_reason`）。
> - **§7 实测产物**：只记测到的客观量（检出相/多型、实测层数、覆盖率、畴尺寸、谱学指标），不判"好/坏"。
>
> "成功/失败"由**分析端**从「目标产物（§1b）↔ 实测产物（§7）+ 过程事件（§6）」推断，而非录入端标签。这样避免主观标签污染训练集，也天然区分"工艺跑完但没长好（真负样本）"与"炉子中断（非材料学结论）"。

**P1（失败即数据）在 v2 的落地 = 留存规则**：任何**已开始**的炉次必须作为正式记录保存，不因"没长好/中断"丢弃或降级为草稿——这是真负样本的唯一来源，事后无法补录。

> **决定（2026-07-06，经 Fable 评审修正）**：
> - **不设主观成败标签**（v1 的 `outcome_category` success/partial/failed 不纳入 v2）——成 / 败由**分析端**从「目标产物 ↔ 实测产物 + 过程事件」推断，免去"这算 failed 还是 partial"的录入端争议。
> - **但保留客观现象**：§7 实测产物设 `观察到的现象` 客观多选词表（无生长 / 不连续覆盖 / 厚层区域 / 可见颗粒沾污 / 衬底破损 / 变色…），定位为"光镜可判的客观描述"而非结论。它是**失败炉次的最小结构化痕迹**——否则最常见的失败（无生长）零结构化记录，真负样本没有负标签，P1 落空。这也回应了设计依据文档引用的 STEP/ReChart（主张记录失败模式）。
> - v1 线上数据的 `quality_label` / `failure_modes` 迁移为独立的"历史标注"层，不删不丢（见 §11 迁移映射）。
>
> **要点**：砍掉的是"主观成败判断"，不是"客观负结果"——二者是范畴不同的两件事。

## 8. 字段字典（模块级导航）

> **逐字段的权威清单在 [`字段草案-v3.xlsx`](字段草案-v3.xlsx)**（工作表 `字段草案`：模块/字段/含义/填写方式/可选项/单位/必填/示例/来源/备注；另含 `v2→v3变更说明`、`待明确清单`）。本节只给模块级导航与必填集，避免与 xlsx 形成第二套真相。

各模块字段构成见 §3 模块清单；完整字段、类型、词表、示例查 xlsx。

### 8.1 必填分级（让"最小可复现集"可被 schema 证明）

- **R0 最小可复现集（不填不能提交）**：
  `实验时间 · 合成方法 · 实验人 · 样品/实验编号 · 目标化学式 · 装置 · 温区数 · 炉体方向 · 前驱体名称 · 前驱体用量 · 衬底材料 · 阶段类型 · 设定温度程序 · 气体组分 · 流量 · 压力体系(生长)`
- **R0 按合成方法条件化**（避免逼出垃圾值）：`前驱体用量(mg)` 仅固态源必填（气态源 / PVD 免）；`目标化学式` 必填（无目标则连"想做什么"都不可知）；PVD 炉次的 R0 由 §8 PVD profile 定义（前驱体名称/用量以靶材替代）。
- **R1 推荐**：影响复现的隐变量（环境湿度、几何细节、批次引用、间隔时间…），提交时黄色警告。
- **R2 选填**：锦上添花。
- 模块 schema 收紧 `additionalProperties`、写明 required —— "最小信息集"这条优点才有 schema 证据（回应导师"自夸 vs 证据"批评）。

### 8.2 相对 v1 的字段级要点（详见 xlsx `v2→v3变更说明`）

- 实验时间(datetime) 置首（t0）；`experiment_type` → `合成方法`（顶层选择器 + CHMO）；`material_system` → `目标产物`（拆出目标层数）。
- 新增 §1b 目标产物；对称性用**体相空间群**（手性/扭转角/堆垛→备注）；结构类型独立下拉。
- 设备：坐标系全局定死；炉管/舟履历 = 重置次数 + 重置后使用次数；外场激励（选项）与 §5 外场参数（定量）分离。
- 前驱体/衬底：**批号引用**替代品牌+批次自由文本；用量只记投料；衬底保留放置朝向、氧化层厚度条件必填。
- 反应条件：阶段类型驱动动态表单；温度 = 设定 + 实测；**新增压力体系/工作压力/本底压力/漏率**；气体词表只留纯气体、混合气拆 components（删 v1 的 Ar+H2 等混合枚举）；MFC 校准不作字段（出厂统一）。
- §6 事件类型与关联对象合并为「事件/部位」。
- §7 表征拆独立表、编号关联；实测产物最小结构化。

## 9. 导出与互操作

- **分析导出（tidy data）**：把嵌套 payload 摊平成扁平长表（precursor_rows / substrate_rows / process_step_rows / gas_rows / characterization_rows …），每行带 `run_code` 等外键，直接拼 ML 训练集。
- **单位随出**：导出附带字段字典 `unit`，下游无需重建单位映射。
- **可查询性**：对 `payload_json` 建 GIN 索引，开放"按温度/前驱体/气体/压力筛选"。
- **未来生态对接**：OPTIMADE `_prefix_` 导出；字段映射 EMMO/CIF/QUDT；数据集版本化发布 + DataCite DOI；合成方法挂 CHMO。

## 10. 合规性（什么叫"符合 cvd_v2"）

一份数据视为 **cvd_v2 兼容**，当且仅当：
1. 以"一炉次 = 一条记录"组织，带唯一 `run_code`；表征以独立记录 + 关联；
2. 模块字段、类型、单位、必填符合 `字段草案-v3.xlsx`；
3. 分类字段取值在 §5 受控词表内（或带机构前缀的合法扩展）；
4. 遵守 §1 原则（P1 失败留存、P2 `null`≠`0`、P3 设定/实测、P4 单位显式）与 §1.2 五判据；
5. 满足 R0 最小可复现集；
6. 通过由本规范生成的机读 JSON Schema 校验。
