## 0. 这份文档是什么 / 不是什么

- **是**：一本带版本号的"规则书 + 设计依据 + 受控词表 + 治理约定"。共同采用同一冻结版本、机读字段字典和引用规则，可以降低机构间数据合并成本；是否适合直接建模仍取决于数据质量、缺失机制和任务定义。
- **不是**：不是软件文档，也不绑定本系统某次实现。本系统（FastAPI + React）是本标准的**参考实现**之一，而非标准本身。

设计目标对齐国际科研数据通行框架 **FAIR**（可发现 / 可访问 / 可互操作 / 可复用）。其中最难的 **可复用（Reusable）** 为首要目标——它依赖"丰富且一致的元数据"，正是本标准的核心。

**v1 → v2 的定位转变**（导师 2026-06-11 组会批评后重构）：
- v1 把工程能力（建站、版本管理、导出）当卖点；v2 降其权重。
- v2 的核心主张 = **"面向气固多相 CVD 的最小可复现元数据标准"本身**：关键科学字段给出机理或文献依据，其余字段记录实验室流程、会议或评审来源；字段经制备同学逐条评审，并参照 NOMAD/GEMD/ESCALATE/2DCC，形成失败溯源路径。

## 1. 设计原则

### 1.1 六条基本原则（P1–P6）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **失败与阴性观察也要留存** | 未观察到目标产物、异常或中断的炉次同样必须保存。它们是分析潜在阴性结果和失败机制的必要证据，但只有在具体任务、判定标准和 ground truth 明确后才能标作 true negative；录入端只留客观事实，不预贴"成/败"标签。 |
| P2 | **`null` ≠ `0`** | 空值 = 未测量 / 未记录；显式 `0` = 测得为零。表单与导入器**不得**把空白强制转成 0。 |
| P3 | **设定值 vs 实测值** | 同一过程量同时存在设定值和实测值时必须分开记录；数值须能标出来源。温度字段 v2 落为「设定温度 + 实测温度」两层（删除 v1 草案曾有的"估算衬底真温"）；流量和压力的逐通道实测结构仍按路线图演进，不把单一字段误称为两者兼具。 |
| P4 | **单位显式且权威** | 每个数值字段采用字段字典指定的 canonical unit，并随导出提供字段字典，不靠字段名后缀猜测。canonical unit 可为 SI 单位或本领域约定单位；流量 sccm 必须绑定参考温度和参考压力。 |
| P5 | **单一权威 + 防漂移** | `field-source.yaml` 是字段、词表和国际化映射的唯一源；Pydantic、JSON Schema、前端元数据和 xlsx 均由它生成并经 CI 漂移校验（见 §6）。 |
| P6 | **对接而非重造** | 复用 FAIR / OPTIMADE / DataCite / EMMO / CHMO 既有生态；只对"CVD-2D 工艺 + 失败"这一真正空白自建词表。 |

### 1.2 字段准入五判据（元数据"到底"的可操作标准）

元数据是描述实验数据及其产生语境的数据；"数据到底、不可再分"是本项目对**字段粒度与原子性**的评审口径，不是 metadata 的通用定义。为保证字段能支持复现和失败溯源，每个候选字段过以下五关，过不了的删：

1. **数值化 / 受控**：能量化的必须数值 + 单位；不能量化的用受控词表，**禁止主观形容词**（如删除 v1 的 clean/normal/contaminated 样品环境枚举，改悬浮粒子浓度数值）。
2. **不可再分**：复合概念拆维度（如"蓝宝石单抛C<0001>"→ 材料/抛光/晶向三字段）。
3. **可溯源**：凡涉及实物（化学品/衬底/气瓶/仪器），记录的是**批次/实体引用**而非名字（见 §3 实体引用）。
4. **有依据**：每个字段写得出"为什么记"；科学量给出机理或文献，流程/治理字段给出会议、规范或评审来源——见字段源和设计依据文档。
5. **来源明确**：数值能区分设定值 / 实测值 / 估计值（P3）。

## 2. 版本与治理

- **语义化版本** `MAJOR.MINOR.PATCH`：MAJOR = 不兼容的字段删除/语义变更；MINOR = 向后兼容的新增字段/新增词表值；PATCH = 文字/标签修订，不改数据形态。
- 数据载荷携带 `schema_version`。仓库参考实现已单轨使用 `cvd_v2`（↔ 2.0.x）；线上仍为切换前旧部署，批8采用整库重建切换，不执行 `cvd_v1 → cvd_v2` 数据迁移。
- datetime 字段保存 ISO 8601 日期时间和 UTC offset；浏览器未提供 offset 的本地时间按部署变量 `EXPERIMENT_TIMEZONE` 解释。纯日期不能代替时刻。
- **受控核心 + 登记扩展**：核心字段集由本规范统一管理；机构特有扩展字段须加机构前缀（参照 OPTIMADE `_provider_`，如 `_pku_chamber_pressure_pa`），不得污染核心命名空间。
- **术语审定**：中文字段名依国标 / 计量规范 / 名词委审定名核证（衬底≠基底、批号≠批次号、环境温湿度≠室内温湿度、吹扫≠洗炉、校准≠标定、晶畴尺寸、覆盖率、随炉冷却/快速冷却、硫属源、悬浮粒子浓度等）。完整对照见设计依据文档 §六。
- **演进治理**：推广期设轻量"标准维护小组"审字段增改；近期以 PI 间轻量协议替代正式委员会（借鉴 CIF/COMCIFS）。

### 2.1 机器值与显示值

- 受控词表的 API/数据库值使用稳定 ASCII code（如 `growth`、`atmospheric_pressure`、`single_side_polished`），不把中文标签当机器主键。
- 界面按当前语言显示中英文标签；用户无需记忆或输入 code。旧中文选项在写入边界归一化为 code，新导出始终输出 code。
- 自由文本保留用户原文；它不是受控词表，不做机械翻译或强制英文化。
- 结构化复合字段使用 `{ "value": ..., "option": ... }`，多选/多条字段使用数组；不再用括号、分号拼接成存储字符串。

## 3. 数据模型总览

**最小记录单元 = 一个炉次（一炉一行）**，`run_code` 唯一标识。

```
ExperimentRun (run_code 唯一标识)
├── 实验级标量（一等列, 可索引/查询）
│     started_at(t0) · synthesis_method · operator · status …
├── 9 个工艺/目标/结果模块（§1–§8，见下）
├── 引用的一等实体（只引用 + 快照冻结，不重复录入）：
│     装置库 Setup · 物料批次库 MaterialLot · 表征仪器 Instrument
├── Samples（样品, 含谱系 parent_sample_id —— 可追溯）
├── FileAssets（Setup/实体版本证据 · 表征原始/派生文件，留校验和）
└── Entity Versions + Audit（实体不可变版本快照 + 炉次审计日志 —— 溯源）

CharacterizationRecord (UUID id)        ← 独立表
└── 同时关联 ExperimentRun 与 Sample（"长一批、表征一批"非一一对应，见 §7）
```

**模块清单（与 `字段草案-v3.xlsx` 一一对应）：**

| § | 模块 | 形态 | 说明 |
|---|---|---|---|
| §1 | 基本信息 basic_info | 对象 | 实验时间(t0置首) · 合成方法(顶层CVD/PVD选择器) · 实验人 · 编号 · 环境温湿度 · 悬浮粒子浓度 |
| §1b | 目标产物 target_product | 对象 | 化学式 · 结构类型 · 目标层数 · 体相空间群 · 形态 · 目标性能 · 备注 |
| §2 | 设备与装置 setup | 对象(引用) | 装置库引用 + 壁型 · 温区数 · 炉体方向 · 管材质/尺寸 · **坐标系(全局定死)** · 外场激励 · 炉管/舟履历 |
| §3 | 前驱体 precursors | **数组** `items[]` | 每种一条：名称/化学式 · CAS · **批次引用** · 角色 · 用量(投料) · 处理方式 · 舟坩埚 · 温区/距离 |
| §4 | 衬底 substrates | **数组** `items[]` | 每片一条：材料 · 化学式/取向 · 氧化层厚度(条件) · 粗糙度 · 尺寸/朝向 · 预处理序列 · 温区/距离 |
| §5 | 反应条件 process_steps | **数组**(按阶段) | 每步一套：阶段类型(驱动动态表单) · 温度(设定+实测) · 气体 · 压力体系 · 时长/循环 · 外场参数 |
| §6 | 过程事件 process_events | **数组** | 客观事件：事件/部位 · 发生时刻 · 中止原因 · 描述/附件（见 §7 结果哲学） |
| §7 | 产物表征 + 实测产物 characterization | **独立表** | 表征类型/仪器 · 测试条件 · 原始数据 + 实测产物(检出相/层数/覆盖率/畴尺寸/谱学) |
| §8 | PVD 专用 pvd_profile | 对象(条件) | 合成方法选 PVD 才启用；靶材/靶基距/功率偏压/气氛/时序/沉积速率。**延后实现、先占位** |

### 3.1 一等实体：引用 + 冻结

对标 NOMAD/GEMD 的 Spec-vs-Run 与 ESCALATE 的 Material-vs-InventoryMaterial：

- **装置库 Setup**：一台炉登记一次，实验只引用；引用时**快照冻结**当时的装置定义（含坐标系原点/轴向定义），事后改装置不影响旧记录。实体带 `版本号`（每次修改 +1，引用锁定该版本）。**实验 §2 的装置属性（壁型/温区数/炉体方向/管径/坐标系…）由所引用 Setup 快照【只读投影】带出，不独立重录**；R0 的温区数/炉体方向由快照满足（避免"同一事实两处录入"）。
- **MaterialLot / Setup / Instrument 均带 `版本号`**（改则新版本，旧引用不受影响）。炉次本身不建立 `experiment_versions`；工艺锁定、实体快照与审计日志分别承担不可变工艺、引用溯源和操作留痕。
- **物料批次库 MaterialLot**：化学身份层（物质名/CAS/分子式）+ 商业批次层（供应商/货号/**批号/纯度/粒径**/形态/开封/存储/证书）。衬底批次子类 + 氧化层厚度/晶向/抛光；气瓶批次 + 纯度等级。实验需要批次级溯源时使用版本引用，纯度、粒径和证据由快照带出；当前 `lot_ref` 为 R1 推荐项，未引用时不得把批次属性伪装为已知。
- **批次引用载荷**：调用方只提交 `entity_id + version`；服务端验证实体类别和材料身份，忽略调用方提供的 snapshot，并从不可变版本重建快照。该规则同时适用于前驱体、衬底和 PVD 靶材。
- **实体附件**：CoA、Setup 图等先通过实体附件端点上传，再以 `file_asset_id + sha256` 写入实体版本。服务端绑定 `entity_type/entity_id/entity_version`；绑定后的附件属于不可变版本证据，不允许删除。

> **注**：MaterialLot / 结构化 Setup / 表征仪器三张一等实体表已在 `字段草案-v3.xlsx` 的 **『一等实体字段表』sheet** 定义（登记级字段，与实验记录 R0 不同）。

### 3.2 记录单元与关联（2026-07-06 拍板）

- **记录最小单元 = 炉次**（`run_code`）；R0 锁定校验挂在炉次上。
- **样品（Sample）= 关联主键**：一炉生成 1..n 个样品（v1 已有，含 `parent_sample_id` 谱系）。
- **表征为独立记录**（UUID 主键），同时外键指向炉次和样品；二者均为必填，不使用模糊的 `run_code` 回退——对应"长一批、表征一批"的真实流程。
- 转移 / 堆垛等后处理，未来作为**挂在样品上的轻量事件**，不改动记录单元。
- 不采用"以样品为全生命周期主线"（2DCC 式平台工程），现阶段课题组 ELN 不背这个复杂度。

## 4. 数值与单位约定

- 单位以字段字典 `unit` 为准（℃ / % / %RH / sccm / mg / Pa / mm / nm / min / W / 个·m⁻³ 等），导出随每个数值输出。
- **`null` ≠ `0`**（P2）。
- API/JSON 中的数值以 JSON number 存储，不使用带单位字符串；单位由字段字典给出。
- **位置/坐标系（全局定死，非逐次可选）**：装置坐标系原点固定、**上游为负、下游为正**，水平与竖直炉一致；逐项只记「温区号 + 距热电偶距离(±, mm)」。坐标系定义在装置库登记一次并随引用冻结。
- 温度 ℃；流量 **sccm（在 Setup 版本中冻结参考温度与参考压力）**；压力 **Pa**（工作压力 + 压力体系 常压APCVD/低压LPCVD/超高真空）；时间 min；湿度 %RH。
- 尺寸结构化为数值（长×宽[×高]），不用 "5x10" 字符串。
- 过程事件使用带 offset 的绝对 datetime，且不得早于炉次 `started_at`；修改炉次开始时间时同样反查已有事件。
- **未来对接**：单位映射 QUDT / EMMO；合成方法挂 CHMO 本体（CVD=CHMO:0001314 / APCVD=0001316 / LPCVD=0001322 / MOCVD=0001324）。

### 4.1 时序数据的落地（避免塞进 payload_json）

实测时序（炉温热电偶、MFC 采集，可达数万点）**不进 `payload_json`**——逐点数组会显著增加载荷、校验和查询成本，也不适合频繁追加。目标落地分三层：

1. **原始曲线** → `FileAsset`（csv / parquet + 校验和；参考实现已有文件与校验和机制）；
2. **时序通道注册**（规划中的轻量表）→ 量纲 / 单位 / `measurement_type`（set / measured / assumed）/ 相对 t0 偏移 / 关联 `run_code` + 步序；对标 NOMAD 的 TimeSeries 四元组 + measurement_type；
3. **派生标量进 payload** → 实际峰温、超调量、保温实测均值、降温速率等；只在字段字典已有对应字段时写入，不以自由键扩展。

因此字段表中的时序语义指向原始文件和后续通道注册，不表示当前可把任意数组直接写进 `payload_json`。

> 用户可扩展词表（品牌/型号、批次、event_type 追加项）允许 MEMBER/ADMIN 写，VIEWER 只读。

**跨字段校验规则（防冗余矛盾）**：
- `合成方法` 的 APCVD/LPCVD 前缀与 `压力体系` 记录同一事实，**以校验规则强制一致**（合成方法=LPCVD ⇒ 生长段压力体系=低压，不一致报错）——保留 AP/LP 名称可读性，冗余由校验消解（已敲定，非二选一悬置）。
- 参考实现采用互斥校验带：`atmospheric_pressure ∈ [80,000, 120,000] Pa`、`low_pressure ∈ (10⁻⁶, 80,000) Pa`、`ultra_high_vacuum ∈ (0, 10⁻⁶] Pa`。这些是本标准的记录一致性边界，不替代具体设备或学科语境中的真空等级定义；类别和数值同时校验，避免只选标签而记录矛盾绝压。
- `gas_species` 只保留纯气体 code；混合气以数组逐项记录组分（例如 Ar + H₂），不能把 `Ar+H2` 当成一个新气体。当前流量字段记录该阶段的数值与流量计来源；各气体分别绑定流量/纯度的成组数组属于后续结构升级。
- 复合体系（`结构类型≠本征`）的 `化学式` 显示串须与 `组成明细` 一致（**以 components 为准**，可自动生成）；`组成明细` 的浓度填 `浓度(at%)`、堆垛填 `层序`，不得一格混用（判据 2 不可再分）。

**目标材料录入规范**（化学式一律使用普通数字，无需输入 Unicode 下标）：

| 结构类型 | 目标材料化学式 | 组成明细 |
|---|---|---|
| 本征 | 单一化学式，如 `MoS2` | 不填 |
| 掺杂 | `掺杂剂:基体`，如 `Nb:MoS2` | 基体和掺杂剂各一行；已知时填名义浓度(at%)；不填层序 |
| 合金 | 名义化学计量，如 `Mo0.5W0.5S2` | 各合金元素或组分一行，角色=合金组分；已知时填名义浓度(at%)；不填层序 |
| 垂直异质结 | `下层/上层`，如 `MoS2/WS2` | 每层一行；层序 1 = 最靠近衬底，向上递增；不填浓度 |
| 横向异质结 | 用 `-` 连接横向域，如 `MoS2-WS2` | 每个横向域一行，角色=横向域；不填浓度和层序 |
| 其他 | 按课题组约定填写 | 逐条记录组分，只填适用的浓度或层序，关系在备注说明 |

掺杂剂浓度已知时必须满足 `0 < at% < 100`；`0 at%` 不构成掺杂，`100 at%` 不再有基体含义。垂直异质结中，所有“下层”的层序必须小于所有“上层”的层序，避免文字角色与堆垛顺序相互矛盾。

`体相空间群`为选填整数，按 International Tables for Crystallography 的国际编号（IT number）记录 `1–230`，例如 2H-MoS₂ 的体相填 `194`。Hermann–Mauguin 符号是该编号的展示/查询信息，不与编号混写在同一存储字段；不清楚时留空。

合金组成明细不得重复；组分元素并集必须覆盖且仅覆盖目标化学式元素。名义浓度要么全部不填，要么全部填写并在 `±0.001` 容差内合计 100 at%。

## 6. 单一权威与防漂移（P5 落地）

字段定义只维护在 `field-source.yaml`；Pydantic model、JSON Schema、前端元数据、字段字典 JSON 和 xlsx 都是可重建生成物。`payload_json` 是依据该契约实存的业务数据，不反向定义字段。

**现行收敛方案：**
- `field-source.yaml` 定义字段语义、类型、单位、数值边界、必填、条件、词表 code 与中英文显示名。
- Pydantic 是 API 写入边界的严格运行时校验器；JSON Schema 是包含工艺模块和结构化结果的对外机读契约。
- `validation` 同步进入 JSON Schema、前端字段元数据和 xlsx 的机器约束列，避免 UI、API 与人读字段表各自猜边界。
- 生成物漂移测试与 `check_field_source.py` 在 CI 中强制所有载体一致，任一生成物单独改动都会失败。

## 7. 结果模型：客观事实优先（v2 的关键立场，相对 v1 有变）

> **v1 立场**：录入端用 `outcome_category`（success/partial/failed/aborted）+ `failure_mode` 受控词表给炉次贴"成败/失败模式"标签。
> **v2 立场（2026-06-24 决定）**：**不在录入端下成败判断**。分两处只记**客观事实**：
> - **§6 过程事件**：如实记客观事件（气流中断、人工干预、计划结束…），不写成"失败"；中止只记客观原因（`abort_reason`）。
> - **§7 实测产物**：只记测到的客观量（检出相/多型、实测层数、覆盖率、畴尺寸、谱学指标），不判"好/坏"。
>
> "成功/失败"由**分析端**在给定任务与判据下，从「目标产物（§1b）↔ 实测产物（§7）+ 过程事件（§6）」推断，而非录入端标签。这样避免主观标签污染训练集，也区分"工艺完成但未观察到目标产物（候选阴性观察）"与"设备中断（不能直接推出材料学阴性）"。

**P1 在 v2 的落地 = 留存规则**：任何**已开始**的炉次都应保留，不因"没长好/中断"删除。`draft` 只是可编辑的生命周期状态，不是丢弃区；记录最终应锁定，或在确需排除时带原因作废，才能保留阴性观察、异常和操作证据。

**结果留存的合规规则（把"客观现象"从选填变成会被填的负标签）**：`观察到的现象` 字段本身选填（不作为锁定硬卡）；但**当炉次锁定且 §7 无任何有效实测证据或表征行时，该炉次进入"结果缺失"待办清单**，直到补录，或显式标注"暂未表征"。管理员可审计解锁，因此 `locked` 是正常业务终态而非绝对不可逆状态。

> **决定（2026-07-06，经 Fable 评审修正）**：
> - **不设主观成败标签**（v1 的 `outcome_category` success/partial/failed 不纳入 v2）——成 / 败由**分析端**从「目标产物 ↔ 实测产物 + 过程事件」推断，免去"这算 failed 还是 partial"的录入端争议。
> - **但保留客观现象**：§7 实测产物设 `观察到的现象` 客观多选词表（无生长 / 不连续覆盖 / 厚层区域 / 可见颗粒沾污 / 衬底破损 / 变色…），定位为"光镜可判的客观描述"而非结论。它是失败或阴性观察的最小结构化证据；是否构成某个分析任务的负标签，必须由下游判据决定。
> - v2 单轨生产切换采用整库重建，不迁移 v1 试运行数据；本标准不定义已作废的 v1→v2 历史标注映射。
>
> **要点**：砍掉的是"主观成败判断"，不是"客观负结果"——二者是范畴不同的两件事。

## 8. 字段字典（模块级导航）

> **逐字段权威清单是 [`field-source.yaml`](field-source.yaml)**。[`字段草案-v3.xlsx`](字段草案-v3.xlsx) 是由它生成的人读视图（工作表 `字段草案`、`v2→v3变更说明`、`待明确清单`），不得手工作为第二套真相维护。本节只给模块级导航与必填集。

各模块字段构成见 §3 模块清单；完整字段、类型、词表、边界、示例以 YAML 和它生成的 xlsx 为准。

### 8.1 必填分级（让"最小可复现集"可被机器验证）

- **R0 最小可复现集（18 项；不满足不能锁定）**：
  `实验时间 · 合成方法 · 实验人 · 炉次编号 · 目标材料化学式 · 结构类型 · 组成明细(非本征) · 装置 · 温区数 · 炉体方向 · 前驱体名称/化学式 · 前驱体用量(非气态) · 衬底材料 · 阶段类型 · 设定温度程序 · 气体组分 · 流量 · 压力体系/工作压力(生长)`。
- **R0 按相态 / 结构类型条件化**（避免逼出垃圾值、让条件可被 schema 评估）：前驱体新增 `相态(固/气/液)` 判别字段，`前驱体用量` 仅 `相态≠气` 时必填（固态 mg、液态 µL/质量；气态源免）；`目标化学式`、`结构类型` 必填；`组成明细` 在 `结构类型≠本征` 时条件必填（复合体系不得只留显示串，见 §1b）。
- **PVD 暂不纳入 v2.0 合规判定**（§8 PVD 为占位 / 延后）：PVD 炉次不参与本 R0 校验，其最小集待 PVD profile 落地时定义。
- **R1 推荐**：影响复现的隐变量（环境湿度、几何细节、批次引用、间隔时间…），界面提示但不阻止锁定。
- **R2 选填**：锦上添花。
- 模块 JSON Schema 收紧 `additionalProperties` 并声明字段内 required；Setup 快照、温区上限、状态和跨实体条件由锁定时服务校验补足。两层共同提供"最小信息集"的机器证据。

### 8.2 相对 v1 的字段级要点（详见 xlsx `v2→v3变更说明`）

- 实验时间(datetime) 置首（t0）；`experiment_type` → `合成方法`（顶层选择器 + CHMO）；`material_system` → `目标产物`（拆出目标层数）。
- 新增 §1b 目标产物；对称性用**体相空间群**（手性/扭转角/堆垛→备注）；结构类型独立下拉。
- 设备：坐标系全局定死；炉管/舟履历 = 重置次数 + 重置后使用次数；外场激励（选项）与 §5 外场参数（定量）分离。
- 前驱体/衬底：**批号引用**替代品牌+批次自由文本；用量只记投料；衬底保留放置朝向、氧化层厚度条件必填。
- 反应条件：阶段类型驱动动态表单；温度 = 设定 + 实测；**新增压力体系/工作绝对压力/本底压力/漏率**；气体词表只留纯气体，混合气拆成数组项。MFC 的通道、适用气体、量程和校准日期在 Setup 中登记并随版本冻结，逐炉不重复录入。
- §6 事件类型与关联对象合并为「事件/部位」。
- §7 表征拆独立表、编号关联；实测产物最小结构化。

## 9. 导出与互操作

- **分析导出（关系型长表）**：保留炉次、前驱体、衬底、过程步、样品、表征结果、文件七张业务表，并用模块明细表展开目标产物、过程事件及其他嵌套字段；每行带 `run_code` 等外键。CSV 的空单元格不能独立区分 `null`、空字符串、空数组和空对象，因此 ZIP 同时提供权威无损 `records.json`。导出适合进入清洗与特征工程，不宣称未经质量控制即可直接作为训练集。
- **单位随出**：导出附带字段字典 `unit`，下游无需重建单位映射。
- **版本随出**：导出附 `schema_manifest`，包含载荷版本、标准版本、字段字典及明细路径约定。
- **可查询性**：当前参考实现支持炉次编号、材料、实验人、日期和状态筛选，并对常用文本列提供 PostgreSQL trigram 索引；按温度、气体和压力等嵌套字段查询属于后续索引/API 范围。
- **未来生态对接**：OPTIMADE `_prefix_` 导出；字段映射 EMMO/CIF/QUDT；数据集版本化发布 + DataCite DOI；合成方法挂 CHMO。

## 10. 合规性（什么叫"符合 cvd_v2"）

一份数据视为 **cvd_v2 兼容**，当且仅当：
1. 以"一炉次 = 一条记录"组织，带唯一 `run_code`；表征以独立记录 + 关联；
2. 模块字段、类型、单位、边界和必填符合 `field-source.yaml`；
3. 分类字段取值在 §5 受控词表内（或带机构前缀的合法扩展）；
4. 遵守 §1 原则（P1 失败留存、P2 `null`≠`0`、P3 设定/实测、P4 单位显式）与 §1.2 五判据；
5. 满足 R0 最小可复现集；
6. 通过由本规范生成的机读 JSON Schema 校验；
7. 终态炉次满足 §7 的**结果留存规则**（有现象 / 表征行，或显式"未表征"标注）。

> **v2.0 合规范围声明**：一等实体（MaterialLot / 装置 / 仪器）字段见 xlsx『一等实体字段表』，**纳入合规**；暂**不含** PVD profile（占位，随后续版本纳入）。
