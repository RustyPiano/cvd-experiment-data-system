# CVD-2D 工艺数据标准 (CVD-2D Process Data Standard) — v2.0（草案 / DRAFT）

> 状态：**DRAFT**，供内部审阅，尚未冻结。
> 规范版本：`2.0.0`（草案）。对应数据载荷 `schema_version = cvd_v2`。
> 版本口径：`2.0.0` 是标准语义版本，`cvd_v2` 是载荷标识，`v3.11` 是冻结前字段表内部修订号；文件名 `字段草案-v3.xlsx` 为沿用的交付物名称，不表示第三套 schema。

> 适用范围：化学气相沉积（CVD）法生长二维材料的**工艺参数 → 客观结果（含失败）** 数据；含物理气相沉积（PVD）延后 profile。
> **权威字段字典**：机读、逐字段的唯一权威源是 [`field-source.yaml`](field-source.yaml)；[`字段草案-v3.xlsx`](字段草案-v3.xlsx)、JSON Schema、后端模型和前端字段元数据均由它生成。本文是**人读规范 + 规则书 + 设计依据 + 词表 + 治理**。

## 0. 这份文档是什么 / 不是什么

- **是**：一本带版本号的"规则书 + 设计依据 + 受控词表 + 治理约定"。共同采用同一冻结版本、机读字段字典和引用规则，可以降低机构间数据合并成本；是否适合直接建模仍取决于数据质量、缺失机制和任务定义。
- **不是**：不是软件文档，也不绑定本系统某次实现。本系统（FastAPI + React）是本标准的**参考实现**之一，而非标准本身。

设计目标对齐国际科研数据通行框架 **FAIR**（可发现 / 可访问 / 可互操作 / 可复用）。其中最难的 **可复用（Reusable）** 为首要目标——它依赖"丰富且一致的元数据"，正是本标准的核心。

**v1 → v2 的定位转变**（导师 2026-06-11 组会批评后重构）：
- v1 把工程能力（建站、版本管理、导出）当卖点；v2 降其权重。
- v2 的核心主张 = **"面向气固多相 CVD 的最小可复现元数据标准"本身**：关键科学字段给出机理或文献依据，其余字段记录实验室流程、会议或评审来源；字段经制备同学逐条评审，并参照 NOMAD/GEMD/ESCALATE/2DCC，形成失败溯源路径。

## 1. 设计原则

### 1.1 六条基本原则（P1–P6）

| # | 原则 | 含义 |
|---|------|------|
| P1 | **失败与阴性观察也要留存** | 未观察到目标产物、异常或中断的炉次同样必须保存。它们是分析潜在阴性结果和失败机制的必要证据，但只有在具体任务、判定标准和 ground truth 明确后才能标作 true negative；录入端只留客观事实，不预贴"成/败"标签。 |
| P2 | **`null` ≠ `0`** | 空值 = 未测量 / 未记录；显式 `0` = 测得为零。表单与导入器**不得**把空白强制转成 0。 |
| P3 | **设定值 vs 实测值** | 同一过程量同时存在设定值和实测值时必须分开记录；数值须能标出来源。温度落为分温区设定程序与实测温度文件引用两层（删除 v1 草案曾有的"估算衬底真温"）；逐气体供气按各自区间记录流量，并可注明测量来源，不用一个共享值代替所有气体。 |
| P4 | **单位显式且权威** | 每个数值字段采用字段字典指定的 canonical unit，并随导出提供字段字典，不靠字段名后缀猜测。canonical unit 可为 SI 单位或本领域约定单位。 |
| P5 | **单一权威 + 防漂移** | `field-source.yaml` 是字段、词表和国际化映射的唯一源；Pydantic、JSON Schema、前端元数据和 xlsx 均由它生成并经 CI 漂移校验（见 §6）。 |
| P6 | **对接而非重造** | 复用 FAIR / OPTIMADE / DataCite / EMMO / CHMO 既有生态；只对"CVD-2D 工艺 + 失败"这一真正空白自建词表。 |

### 1.2 字段准入五判据（元数据"到底"的可操作标准）

元数据是描述实验数据及其产生语境的数据；"数据到底、不可再分"是本项目对**字段粒度与原子性**的评审口径，不是 metadata 的通用定义。为保证字段能支持复现和失败溯源，每个候选字段过以下五关，过不了的删：

1. **数值化 / 受控**：能量化的必须数值 + 单位；不能量化的用受控词表，**禁止主观形容词**（如删除 v1 的 clean/normal/contaminated 样品环境枚举；实验环境保留每炉实填的温度和湿度）。
2. **不可再分**：复合概念拆维度（如"蓝宝石单抛C<0001>"→ 材料/抛光/晶向三字段）。
3. **可溯源**：凡涉及实物（化学品/衬底/气瓶/仪器），记录的是**批次/实体引用**而非名字（见 §3 实体引用）。
4. **有依据**：每个字段写得出"为什么记"；科学量给出机理或文献，流程/治理字段给出会议、规范或评审来源——见字段源和设计依据文档。
5. **来源明确**：数值能区分设定值 / 实测值 / 估计值（P3）。

## 2. 版本与治理

- **语义化版本** `MAJOR.MINOR.PATCH`：MAJOR = 不兼容的字段删除/语义变更；MINOR = 向后兼容的新增字段/新增词表值；PATCH = 文字/标签修订，不改数据形态。
- 数据载荷携带 `schema_version`。仓库与生产参考实现均单轨使用 `cvd_v2`（↔ 2.0.x）；2026-07-24 生产切换使用全新 v2 数据库，旧 v1 数据库离线归档，不执行 `cvd_v1 → cvd_v2` 数据迁移。
- datetime 字段保存 ISO 8601 日期时间和 UTC offset；浏览器未提供 offset 的本地时间按部署变量 `EXPERIMENT_TIMEZONE` 解释。纯日期不能代替时刻。
- **受控核心 + 登记扩展**：核心字段集由本规范统一管理；机构特有扩展字段须加机构前缀（参照 OPTIMADE `_provider_`，如 `_pku_chamber_pressure_pa`），不得污染核心命名空间。
- **术语审定**：中文字段名依国标 / 计量规范 / 名词委审定名核证（衬底≠基底、批号≠批次号、环境温湿度≠室内温湿度、气路置换≠洗炉、校准≠标定、晶畴尺寸、覆盖率、随炉冷却/快速冷却、硫属源等）。完整对照见设计依据文档 §六。
- **演进治理**：推广期设轻量"标准维护小组"审字段增改；近期以 PI 间轻量协议替代正式委员会（借鉴 CIF/COMCIFS）。

### 2.1 机器值与显示值

- 受控词表的 API/数据库值使用稳定 ASCII code（如 `reaction_conditions`、`atmospheric_pressure`、`single_side_polished`），不把中文标签当机器主键。
- 界面按当前语言显示中英文标签；用户无需记忆或输入 code。旧中文选项在写入边界归一化为 code，新导出始终输出 code。
- 自由文本保留用户原文；它不是受控词表，不做机械翻译或强制英文化。
- 结构化复合字段使用 `{ "value": ..., "option": ... }`，多选/多条字段使用数组；不再用括号、分号拼接成存储字符串。

## 3. 数据模型总览

**最小记录单元 = 一个炉次（一炉一行）**，`run_code` 唯一标识。

```
ExperimentRun (run_code 唯一标识)
├── 实验级标量（一等列, 可索引/查询）
│     started_at(t0) · synthesis_method · operator · status …
├── 模块化工艺/目标/事件载荷（§1–§8，见下）
├── 引用的一等实体（只引用 + 快照冻结，不重复录入）：
│     装置库 Setup · 物料批次库 MaterialLot · 表征仪器 Instrument
├── Samples（样品, 含谱系 parent_sample_id —— 可追溯）
├── FileAssets（实体证据 · 实测温度 · 过程事件 · 直接观察 · 表征文件，留校验和与绑定）
└── Entity Versions + Audit（实体不可变版本快照 + 炉次审计日志 —— 溯源）

Result（统一写入/读取契约，kind = direct_observation | characterization）
└── 同时关联 ExperimentRun 与 Sample；表征记录仍以 UUID 独立存储（见 §7）
```

**模块清单（与 `字段草案-v3.xlsx` 一一对应）：**

| § | 模块 | 形态 | 说明 |
|---|---|---|---|
| §1 | 基本信息 basic_info | 对象 | 实验时间(t0置首) · 合成方法(顶层CVD/PVD选择器) · 实验人 · 系统生成编号 · 环境温湿度 · 实验前检查 |
| §1b | 目标产物 target_product | 对象 | 化学式 · 结构类型/组成明细 · 目标层数 · 体相空间群 · 目标形态 · 目标性能 · 备注 |
| §2 | 设备与装置 setup | 对象(引用) | 装置库引用 + 壁型 · 温区数 · 炉体方向 · 管材质/尺寸 · **坐标系(全局定死)** · 各温区传感器/不确定度 · 外场能力 |
| §3 | 前驱体装载 source_loads | **数组** `items[]` | 每个物理装载一条：物料批次 · 工艺作用(选填多选) · 用量 · 处理步骤 · 舟/坩埚或具体衬底片 · 温区/位置 |
| §4 | 衬底 substrates | **数组** `items[]` | 每片一条：材料/批次 · 化学式/晶向 · 氧化层厚度(条件) · 粗糙度 · 具名尺寸/放置 · 预处理序列 · 温区/距离 |
| §5 | 实验过程 process_steps | **判别数组** | 一条预处理 + 一条反应条件；可追加具名其他记录。反应条件含分温区程序、实测温度文件、逐气体多区间、绝对压力、时长/循环、降温与实际外场 |
| §6 | 过程事件 process_events | **数组** | 稳定事件 ID · 客观事件 · 发生时刻 · 是否终止/终止原因 · 说明 · 处理措施 · 事件绑定附件 |
| §7 | 结果 results | **统一契约** | 直接观察或表征二选一；均关联炉次与样品，记录客观现象/实测量及对应证据文件，不下成败判断 |
| §8 | PVD 专用 pvd_profile | 对象(条件) | 合成方法选 PVD 才启用；靶材/靶基距/功率偏压/气氛/时序/沉积速率。**延后实现、先占位** |

### 3.1 一等实体：引用 + 冻结

对标 NOMAD/GEMD 的 Spec-vs-Run 与 ESCALATE 的 Material-vs-InventoryMaterial：

- **装置库 Setup**：一台炉登记一次，实验只引用；引用时**快照冻结**当时的装置定义（含坐标系、各温区温度传感器、外场能力），事后改装置不影响旧记录。实体带 `版本号`（每次修改 +1，引用锁定该版本）。系统以不可变 UUID 识别装置；实验室装置编号保持唯一，管理员可通过新版本纠正录入错误，历史版本保留原编号。装置来源必填，并只展开对应的身份字段：商业设备填写制造商或品牌、型号；实验室自制填写设计或建造单位、内部型号；改造设备填写原设备制造商或品牌、原设备型号、改造内容。三类装置共用同一套技术字段，改造不另设版本字段，直接使用实体版本历史。**实验 §2 的装置属性（壁型/温区数/炉体方向/截面尺寸/坐标系等）由所引用 Setup 快照【只读投影】带出，不独立重录**。圆形、方形、矩形截面分别记录外径、外边长、外宽与外高，并共同记录壁厚；`temperature_sensors[]` 必须以 `zone_index` 恰好覆盖 `1..zone_count`，每区记录传感器类别；设备资料明确提供时可选填 `nominal_accuracy_C`；`field_devices` 只表示装置具备的等离子体、光、电能力，不等于本炉实际启用。
- **MaterialLot / Setup / Instrument 均带 `版本号`**（改则新版本，旧引用不受影响）。炉次本身不建立 `experiment_versions`；工艺锁定、实体快照与审计日志分别承担不可变工艺、引用溯源和操作留痕。
- **物料批次库 MaterialLot**：化学品与衬底记录适用的物质名/CAS/分子式及商业批次信息；气瓶没有强制单一化学式，而以 `gas_components[]` 记录标签或 CoA 声明的固定组成。单组分 100 vol% 表示纯气，多组分且合计 100 vol% 表示供应商预混气。粒径仅属于化学品，粉末/箔/靶等形态不适用于气瓶。衬底批次保存材料、氧化层、晶向与抛光、偏切和标称粗糙度；晶向/抛光与偏切分别显式记录“有规格数值 / 供应商未提供 / 不适用”，只有有规格时展开明细，禁止用虚构晶向或偏切角 `0` 代替未知。当前 R0 要求前驱体与衬底使用版本引用，气路置换与反应供气也引用实际气瓶批次；批次事实与证据由冻结快照带出，不得把未引用的批次属性伪装为已知。
- **批次引用载荷**：调用方只提交 `entity_id + version`；服务端验证实体类别和材料身份，忽略调用方提供的 snapshot，并从不可变版本重建快照。该规则同时适用于前驱体、衬底和 PVD 靶材。
- **实体附件**：CoA、Setup 图等先通过实体附件端点上传，再以 `file_asset_id + sha256` 写入实体版本。服务端绑定 `entity_type/entity_id/entity_version`；绑定后的附件属于不可变版本证据，不允许删除。

> **注**：MaterialLot / 结构化 Setup / 表征仪器三张一等实体表已在 `字段草案-v3.xlsx` 的 **『一等实体字段表』sheet** 定义（登记级字段，与实验记录 R0 不同）。

### 3.2 记录单元与关联（2026-07-06 拍板）

- **记录最小单元 = 炉次**（`run_code`）；R0 锁定校验挂在炉次上。
- **样品（Sample）= 关联主键**：一炉生成 1..n 个样品（v1 已有，含 `parent_sample_id` 谱系）。
- **表征为独立记录**（UUID 主键），同时外键指向炉次和样品；二者均为必填，不使用模糊的 `run_code` 回退——对应"长一批、表征一批"的真实流程。
- 转移 / 堆垛等后处理，未来作为**挂在样品上的轻量事件**，不改动记录单元。
- 不采用"以样品为全生命周期主线"（2DCC 式平台工程），现阶段课题组 ELN 不背这个复杂度。

## 4. 数值与单位约定

- 单位以字段字典 `unit` 为准（℃ / % / %RH / sccm / mg / Pa / mm / nm / min / W / 个·m⁻³ 等），导出随每个数值输出。
- **`null` ≠ `0`**（P2）。
- API/JSON 中的数值以 JSON number 存储，不使用带单位字符串；单位由字段字典给出。
- **位置/坐标系（全局定死，非逐次可选）**：装置坐标系原点固定、**上游为负、下游为正**，水平与竖直炉一致；逐项只记「温区号 + 距热电偶距离(±, mm)」。坐标系定义在装置库登记一次并随引用冻结。
- 温度 ℃；逐气体区间流量 **sccm**；压力 **Pa**（工作绝对压力 + 反应压力条件 常压APCVD/低压LPCVD/超高真空）；时间 min；湿度 %RH。
- 尺寸结构化为数值（长×宽[×高]），不用 "5x10" 字符串。
- 过程事件使用带 offset 的绝对 datetime，且不得早于炉次 `started_at`；修改炉次开始时间时同样反查已有事件。
- **未来对接**：单位映射 QUDT / EMMO；合成方法挂 CHMO 本体（CVD=CHMO:0001314 / APCVD=0001316 / LPCVD=0001322 / MOCVD=0001324）。

### 4.1 时序数据的落地（避免塞进 payload_json）

高频实测温度点**不直接塞进 `payload_json`**。现行契约分三层：

1. **设定程序**写入 `temperature_program.zones[]`；每区包含严格按 `elapsed_min` 递增的 `{elapsed_min, setpoint_C}` 点，数值温度必须高于绝对零度，不接受任意字符串温度。
2. **实测温度原始曲线**写入同炉次的 `FileAsset`（角色 `temperature_timeseries`，留校验和），反应条件仅保存 `{file_asset_id, time_column, channels:[{zone_index,column_name}]}` 引用。通道温区和列名各自唯一，温区不得超出 Setup。
3. **派生标量**只在字段字典已有明确字段时写入，不以自由键扩展。

实测温度文件必须有效、属于同一炉次并绑定到反应条件；删除引用时，参考实现同步软删除不再被引用的过程文件。该结构把设定值、原始实测证据和字段字典中的派生量分开，不把文件名或自由文本冒充测量数据。

## 5. 受控词表（Controlled Vocabularies）

分类字段取值受控。**下表为便览节选，权威取值以 `field-source.yaml` 为准；`字段草案-v3.xlsx` 是由它生成的人读视图**：

| 字段/词表键 | 取值（节选） | 用户可扩展 |
|---|---|---|
| `synthesis_method` | CVD / APCVD / LPCVD / PECVD / MOCVD / 盐辅助CVD / PVD-磁控溅射 / PVD-热蒸发 / PLD / other（挂 CHMO） | 否 |
| `structure_type` | 本征 / 掺杂 / 合金 / 垂直异质结 / 横向异质结 / other（单选判别器） | 否 |
| `target_morphology` | 连续膜 / 纳米片(flake) / 纳米带 / 纳米管 / 纳米棒 / 纳米颗粒 / other | 否 |
| `wall_type` | 热壁 / 冷壁 | 否 |
| `orientation` | 水平 / 垂直 | 否 |
| `tube_material_shape` | 结构化对象：材质 = 石英、刚玉、other；截面 = 圆形、方形、矩形、other；两个维度独立保存 | 否 |
| `source_loads[].ingredients[].process_roles` | 促进反应或成核 / 助熔或盐辅助 / 输运 / 溶剂或分散介质 / 还原 / 氧化 / 刻蚀 / other（选填多选） | **是**（other 需具名） |
| `treatment_steps[].type` | 直接加载 / 熔融凝固 / 压片 / 旋涂 / 退火 / 研磨 / other | 否 |
| `substrates.items[].material` | SiO₂/Si · 蓝宝石(Al₂O₃) · 石英 · 云母 · Cu箔 · Au箔 · h-BN · other | 否 |
| `pretreatment_steps[].type` | 清洗 / 退火 / 等离子体处理 / 亲水化 / other（有序序列） | 否 |
| `process_timeline` | 系统准备、分温区温度程序、逐气体使用时段与降温条件；不要求声明不可直接观测的反应起点 | 否 |
| `pressure_system` | 常压(APCVD) / 低压(LPCVD) / 超高真空 | 否 |
| `gas_feeds[].species` | Ar / N₂ / H₂ / O₂ / CH₄ / other（只保留单一气体身份；混合供气拆成多条） | 否 |
| `event_type` | 供电中断 · 供水中断 · 供气中断 · 管路堵塞 · 压力突变 · 信号异常 · 人工干预 · 设备报警 · 具名其他事件 | **是**（保存明确名称） |
| `termination_reason` | 设备报警 / 人工停止 / 计划变更 / other | 否 |
| `method_instrument` | 光镜 / SEM / Raman / 低波数Raman / PL / AFM / XRD / TEM / other | 否 |
| `setup_origin` / `manufacturer_brand` / `model` / `lot_ref` | （实验室登记/引用） | **是** |

每条目标产物只能选择一个 `structure_type`。选择后页面立即切换对应的化学式与组成明细填写规则；本征不填 `components[]`，其他类型显示且条件必填 `components[]`。

> 实体登记项（品牌/型号、批次）由实验室成员维护。凡契约设有 `*_other` 或“其他名称”字段的选择，other 与具名明细必须同时出现或同时为空。

前驱体成分与目标产物的重合关系不再由用户选择“金属源/硫族元素源/掺杂源”等交叉分类；该信息可由物料与目标化学式派生。仅记录无法从化学式确定的本炉工艺作用，允许多选或留空。旋涂作为一个处理步骤，其 `stages[]` 按数组顺序记录每段必填的转速和时长；溶液浓度则属于本次使用的物料，数值与受控单位成对保存。选择涂覆在衬底表面时，装载须通过稳定 `source_id` 关联至少一片本炉衬底，并继承其温区与位置。

**生长条件结构（字段表 §5，现行内部验证契约）**：

- 新建表单不让用户选择抽象“工艺阶段”或声明不可直接观测的反应起点。用户按实际操作填写持续时间，系统统一以实验开始为 `t0`，自动换算温度与气体程序的绝对时间。
- `preparation_operations[]` 为选填的实验前操作，按顺序记录抽气 `pump_down`、气路置换 `gas_exchange`、检漏 `leak_check` 或具名其他操作。每项填写持续时间；气路置换再选择实际气瓶版本 `gas_sources[]` 并填写循环次数。一瓶预混气是一项来源，现场混合则引用多个实际气瓶；固定组成只在气瓶批次登记一次。
- 各温区温度程序先记录实验开始时的设定温度，后续每步只填写“本步用时 + 到达或保持的温度”。绝对时间由系统累加；相邻同温点表达保温，不要求用户判断升温、稳定或成核阶段。
- 每种气体独立绑定气瓶批次和流量来源。供气时段可选择整个过程；不覆盖全程时填写相对实验开始的实际起止时间，同一气体的自定义区间不得重叠。
- 继续硫化/硒化、退火和气体切换直接由温度步骤与气体时段表达，不再制造“反应后处理”副本。过程压力记录类别；常压不伪造精确压力值，低压、超高真空或其他压力条件记录正的绝对压力；降温按实际方式展开必要参数。
- `field_params[]` 只记录本炉实际启用的等离子体、光或电场及其时间区间、具名参数；其 `field_type` 必须已出现在所引 Setup 的 `field_devices` 能力中。

**过程事件与附件（字段表 §6）**：

- 每条事件有稳定且唯一的 `event_id`，编辑或排序不得改变；记录客观 `event_type`、带 offset 的 `occurred_at`、`terminated_run`、说明和处理措施。只有 `terminated_run=true` 时填写终止原因，正常计划结束不作为异常终止。
- `attachment_file_ids[]` 只引用同炉次、角色为 `process_event_attachment`、且以该 `event_id` 绑定的有效 FileAsset。事件附件绑定到稳定 ID，而不是会随排序变化的数组下标。

**跨字段校验规则（防冗余矛盾）**：
- `合成方法` 的 APCVD/LPCVD 前缀与 `反应压力条件` 记录同一事实，**以校验规则强制一致**（合成方法=LPCVD ⇒ 反应压力条件=低压，不一致报错）——保留 AP/LP 名称可读性，冗余由校验消解（已敲定，非二选一悬置）。
- 参考实现采用互斥校验带：常压只记录 `atmospheric` 类别且不保存精确压力通道；`low_pressure ∈ (10⁻⁶, 80,000) Pa`、`ultra_high_vacuum ∈ (0, 10⁻⁶] Pa`，其他压力条件保存正的绝对压力。这些是记录一致性边界，不替代具体设备或学科语境中的真空等级定义。
- `species` 只保留单一气体 code；混合气以逐气体通道记录（例如 Ar 和 H₂ 各一条），不能把 `Ar+H2` 当成一个新气体。每条供气记录独立绑定气瓶批次、多段流量区间，并可独立注明测量来源。
- 实验前气路置换引用物理气瓶版本：预混气的比例来自该版本的 `gas_components[]`，现场混合引用多个纯气瓶；不得只保存 `Ar+H2` 名称，也不得由名称猜测批号。
- 复合体系（`结构类型≠本征`）的 `化学式` 显示串须与 `组成明细` 一致（**以 components 为准**，可自动生成）；`组成明细` 的浓度填 `浓度(at%)`、堆垛填 `层序`，不得一格混用（判据 2 不可再分）。

**目标材料录入规范**（化学式输入框会即时校验元素与语法）：

| 结构类型 | 目标材料化学式 | 组成明细 |
|---|---|---|
| 本征 | 单一化学式，如 `MoS2` | 不填 |
| 掺杂 | `掺杂剂:基体`，如 `Nb:MoS2` | 基体和掺杂剂各一行；已知时填名义浓度(at%)；不填层序 |
| 合金 | 名义化学计量，如 `Mo0.5W0.5S2` | 各合金元素或组分一行，角色=合金组分；已知时填名义浓度(at%)；不填层序 |
| 垂直异质结 | `下层/上层`，如 `MoS2/WS2` | 每层一行；层序 1 = 最靠近衬底，向上递增；不填浓度 |
| 横向异质结 | 用 `-` 连接横向域，如 `MoS2-WS2` | 每个横向域一行，角色=横向域；不填浓度和层序 |
| 其他 | 按课题组约定填写 | 逐条记录组分，只填适用的浓度或层序，关系在备注说明 |

掺杂剂浓度已知时必须满足 `0 < at% < 100`；`0 at%` 不构成掺杂，`100 at%` 不再有基体含义。垂直异质结中，所有“下层”的层序必须小于所有“上层”的层序，避免文字角色与堆垛顺序相互矛盾。

`体相空间群`为选填整数，按 International Tables for Crystallography 的国际编号（IT number）记录 `1–230`，例如 2H-MoS₂ 的体相填 `194`。Hermann–Mauguin 符号是该编号的展示/查询信息，不与编号混写在同一存储字段；不清楚时留空。

合金组成明细不得重复；组分元素并集必须覆盖且仅覆盖目标化学式元素。名义浓度要么全部不填，要么全部填写并在 `±0.001` 容差内合计 100 at%。

## 6. 单一权威与防漂移（P5 落地）

字段定义只维护在 `field-source.yaml`；Pydantic model、JSON Schema、前端元数据、字段字典 JSON 和 xlsx 都是可重建生成物。`payload_json` 是依据该契约实存的业务数据，不反向定义字段。

**现行收敛方案：**
- `field-source.yaml` 定义字段语义、类型、单位、数值边界、必填、条件、词表 code 与中英文显示名。
- Pydantic 是 API 写入边界的严格运行时校验器；JSON Schema 是包含工艺模块和结构化结果的对外机读契约。
- `validation` 同步进入 JSON Schema、前端字段元数据和 xlsx 的机器约束列，避免 UI、API 与人读字段表各自猜边界。
- 生成物漂移测试与 `check_field_source.py` 在 CI 中强制所有载体一致，任一生成物单独改动都会失败。

## 7. 结果模型：客观事实优先（v2 的关键立场，相对 v1 有变）

> **v1 立场**：录入端用 `outcome_category`（success/partial/failed/aborted）+ `failure_mode` 受控词表给炉次贴"成败/失败模式"标签。
> **v2 立场（2026-06-24 决定）**：**不在录入端下成败判断**。分两处只记**客观事实**：
> - **§6 过程事件**：如实记客观事件（供气中断、人工干预、设备报警等），不写成"失败"；提前终止只记客观原因（`termination_reason`）。
> - **§7 结果**：直接观察或表征均只记客观现象、检出相/多型、实测层数、覆盖率、畴尺寸、成核密度、谱学指标及证据文件，不判"好/坏"。
>
> "成功/失败"由**分析端**在给定任务与判据下，从「目标产物（§1b）↔ 实测产物（§7）+ 过程事件（§6）」推断，而非录入端标签。这样避免主观标签污染训练集，也区分"工艺完成但未观察到目标产物（候选阴性观察）"与"设备中断（不能直接推出材料学阴性）"。

**P1 在 v2 的落地 = 留存规则**：任何**已开始**的炉次都应保留，不因"没长好/中断"删除。`draft` 只是可编辑的生命周期状态，不是丢弃区；记录最终应锁定，或在确需排除时带原因作废，才能保留阴性观察、异常和操作证据。

### 7.1 统一结果契约与证据

每条结果都关联一个炉次中的明确样品，并以 `kind` 区分两类：

- `direct_observation`（直接观察）：必须至少提供一个受控的 `observed_phenomena`，或一个/多个 `direct_observation_file`。文件必须有效且同时属于该炉次和样品；直接观察不得混入表征方法、仪器、测试条件、谱学或其他表征专用字段。
- `characterization`（表征）：`method_instrument` 必填。若引用仪器，`instrument_id` 与 `instrument_version` 必须成对提供并冻结版本快照，且方法须在该仪器登记的能力内。表征附件不放在直接观察的 `file_asset_ids` 中，必须通过表征文件端点绑定到对应表征记录。

“其他”必须保留实际含义：

- `method_instrument=other` 时 `method_other` 必填；不是 other 时禁止残留 `method_other`。
- `observed_phenomena` 包含 other 时 `observed_phenomena_other` 必填；不包含 other 时禁止残留该明细。
- 空白明细或孤立的 other 机器值不构成有效结果证据，不能清除“结果缺失”待办。

有效结果证据包括具名客观现象、实测量/结构化指标、同炉次样品绑定的直接观察文件，或有效的表征文件。**当炉次锁定且 §7 没有任何有效证据时，该炉次进入“结果缺失”待办清单**，直到补录，或由用户显式标注“暂未表征”。管理员可审计解锁，因此 `locked` 是正常业务终态而非绝对不可逆状态。

> **决定（2026-07-06，经 Fable 评审修正）**：
> - **不设主观成败标签**（v1 的 `outcome_category` success/partial/failed 不纳入 v2）——成 / 败由**分析端**从「目标产物 ↔ 实测产物 + 过程事件」推断，免去"这算 failed 还是 partial"的录入端争议。
> - **但保留客观现象**：§7 实测产物设 `观察到的现象` 客观多选词表（无生长 / 不连续覆盖 / 厚层区域 / 可见颗粒沾污 / 衬底破损 / 变色…），定位为"光镜可判的客观描述"而非结论。它是失败或阴性观察的最小结构化证据；是否构成某个分析任务的负标签，必须由下游判据决定。
> - v2 单轨生产切换采用整库重建，不迁移 v1 试运行数据；本标准不定义已作废的 v1→v2 历史标注映射。
>
> **要点**：砍掉的是"主观成败判断"，不是"客观负结果"——二者是范畴不同的两件事。

## 8. 字段字典（模块级导航）

> **逐字段权威清单是 [`field-source.yaml`](field-source.yaml)**。[`字段草案-v3.xlsx`](字段草案-v3.xlsx) 是由它生成的人读视图（工作表 `字段草案`、`v2→v3变更说明`、`待明确清单`），不得手工作为第二套真相维护。本节只给模块级导航与必填集。

各模块字段构成见 §3 模块清单；完整字段、类型、词表、边界、示例以 YAML 和它生成的 xlsx 为准。

### 8.1 必填分级（让"最小可复现集"可被机器验证）

- **R0 最小可复现集以当前科学对象契约为准；不满足不能锁定**：
  - 基本信息：`started_at · synthesis_method(CVD) · run_code · created/performed/recorded contributor · precheck.confirmed`。环境温湿度可保存带数值、时间与来源的测量对象，也可明确标记 `not_measured`；不得以 0 冒充未测量。
  - 目标产物：`architecture_type` 与至少一个合法 `material_regions[]`；层序、横向区域和组成关系按所选架构校验。目标形态、目标层数、取向与优化目标均为选填。
  - 装置：冻结的 Setup 身份/版本/快照、完整覆盖 `1..N` 的温区传感器，以及本炉炉管清洗或更换后的使用履历。
  - 前驱体装载：至少一个装载及物料批次版本；非气态实际投料的用量与单位必填且用量大于 0。独立舟/坩埚记录加热温区和相对热电偶位置；衬底表面装载关联本炉具体衬底片。
  - 衬底：至少一片带冻结批次版本、唯一片标记、正的实际长宽、合法放置方式和有效温区位置；晶向、粗糙度、预处理和备注不作为 R0。
  - 过程：每个温区一条从 `t=0` 开始且时间严格递增的设定温度通道；至少一条带气瓶批次、正流量和不重叠时段的反应供气通道；合法压力条件与降温方式。系统准备和抽象过程段均可为空，实际填写时再校验。
- **R0 按实际操作条件化**：常压不要求精确压力通道；非大气压力要求一个正的绝对压力值；受控降温、开盖降温和具名其他降温仅展开各自必要参数。过程文件、外场、事件与位置程序均为选填，但一旦存在就必须通过同炉附件、装置能力与时间一致性校验。
- **锁定与诊断共用语义**：草稿预检读取当前模块载荷；锁定/复核记录读取指定不可变 `RunRevision` 内容与冻结投影，并复验修订归属和 SHA-256。不得用炉次状态“已锁定”替代合规检查。
- **PVD 暂不纳入 v2.0 合规判定**（§8 PVD 为占位 / 延后）：PVD 炉次不参与本 R0 校验，其最小集待 PVD profile 落地时定义。
- **R1 推荐**：影响复现但当前不阻止锁定的隐变量（如炉管几何、源/样品温区距离、降温参数、装置示意图），界面提示但不阻止锁定。
- **R2 选填**：锦上添花。
- 模块 JSON Schema 收紧 `additionalProperties` 并声明字段内 required；Setup 快照、温区上限、状态和跨实体条件由锁定时服务校验补足。两层共同提供"最小信息集"的机器证据。

### 8.2 相对 v1 的字段级要点（详见 xlsx `v2→v3变更说明`）

- 实验时间(datetime) 置首（t0）；`experiment_type` → `合成方法`（顶层选择器 + CHMO）；`material_system` → `目标产物`（拆出目标层数）。
- 新增 §1b 目标产物；对称性用**体相空间群**（手性/扭转角/堆垛→备注）；结构类型独立下拉。
- 设备：坐标系全局定死；炉管材质、截面及按截面形状展开的具名尺寸与壁厚分别记录；Setup 登记各温区传感器/不确定度和外场能力，本炉实际外场在反应条件中记录。
- 前驱体/衬底：**版本化批次引用**替代品牌+批次自由文本；用量只记投料；衬底保留化学式、晶向、粗糙度、具名尺寸/放置和氧化层厚度条件。
- 实验过程：用户按操作和持续时间填写；温度按温区记录起始设定值及后续步骤用时，气体按品种独立绑定气瓶并记录全程或自定义时段，过程压力、降温和外场分别结构化，不另行声明反应起点或重复的反应后处理。
- §6：过程事件使用稳定 UUID，并独立保存事件名称、发生时刻、是否终止/原因、说明、措施和事件附件。
- §7：直接观察与表征共用统一结果契约；表征仍保留独立记录/仪器快照和专用文件绑定；method other 与 phenomena other 均保存具名明细。

## 9. 导出与互操作

- **分析导出（关系型长表）**：分别展开炉次、前驱体、衬底、过程记录、过程事件、样品、统一结果和文件等业务表；每行带 `run_code` 等外键。`files.csv` 明确提供 `file_id / binding_type / binding_id`，使实测温度、过程事件、直接观察和表征文件的归属可恢复。CSV 的空单元格不能独立区分 `null`、空字符串、空数组和空对象，因此 ZIP 同时提供权威无损 `records.json`。导出适合进入清洗与特征工程，不宣称未经质量控制即可直接作为训练集。
- **单位随出**：导出附带字段字典 `unit`，下游无需重建单位映射。
- **版本随出**：导出附 `schema_manifest`，包含载荷版本、标准版本、字段字典及明细路径约定。
- **可查询性**：当前参考实现支持炉次编号、材料、实验人、日期和状态筛选，并对常用文本列提供 PostgreSQL trigram 索引；按温度、气体和压力等嵌套字段查询属于后续索引/API 范围。
- **未来生态对接**：OPTIMADE `_prefix_` 导出；字段映射 EMMO/CIF/QUDT；数据集版本化发布 + DataCite DOI；合成方法挂 CHMO。

## 10. 合规性（什么叫"符合 cvd_v2"）

一份数据视为 **cvd_v2 兼容**，当且仅当：
1. 以"一炉次 = 一条记录"组织，带唯一 `run_code`；表征以独立记录 + 关联；
2. 模块字段、类型、单位、边界和必填符合 `field-source.yaml`；
3. 分类字段取值在 §5 受控词表内（或带机构前缀的合法扩展）；
4. 遵守 §1 原则（P1 失败留存、P2 `null`≠`0`、P3 设定/实测、P4 单位显式）与 §1.2 五判据；
5. 满足 R0 最小可复现集；
6. 通过由本规范生成的机读 JSON Schema 校验；
7. 终态炉次满足 §7 的**结果留存规则**（有有效客观现象、实测量、直接观察/表征文件之一，或显式“暂未表征”标注；孤立 other 不算证据）。

> **v2.0 合规范围声明**：一等实体（MaterialLot / 装置 / 仪器）字段见 xlsx『一等实体字段表』，**纳入合规**；暂**不含** PVD profile（占位，随后续版本纳入）。
