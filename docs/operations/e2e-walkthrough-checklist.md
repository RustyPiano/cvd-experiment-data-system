# CVD 浏览器 E2E 走查清单

> 适用于 2026-07-16 确认的炉次优先工作流。执行时使用一次性本地环境，不连接或修改生产数据；批 8 前禁止运行 `deploy.sh`。

## 1. 验收目标

完整验证以下用户主线：

`开始炉次 → 分节保存 → 锁定工艺 → 自动生成样品 → 其他成员补结果 → 检索、追溯与导出`

同时确认中英文文案、权限边界、附件证据链和浏览器控制台没有功能性异常。

## 2. 一次性本地环境

1. 使用临时 SQLite 数据库和临时文件目录，执行 Alembic 升级。
2. 创建 1 个管理员和 2 个普通成员；成员 A 记录并锁定炉次，成员 B 协作补结果。
3. 启动后端 `8000` 端口和前端 `3000` 端口，Vite 代理 `/api` 到后端。
4. 浏览器视口使用 `1280 × 720`；关键节点截图保存在当次 `mktemp` 验收目录的 `screenshots/` 下。
5. 验收结束后停止两个开发服务，删除临时数据库、上传目录和临时凭据。

## 3. 走查步骤

| # | 操作 | 验收点 |
|---|---|---|
| 1 | 使用管理员登录，进入默认首页 | 默认进入“炉次记录”；导航仅包含炉次记录、样品和基础资料；界面不出现 v2、R0、锁版引用、元数据 JSON 等开发或治理术语 |
| 2 | 在基础资料中分别新增物料批次、实验装置、表征仪器，并为至少一项追加版本 | 新建与版本历史可正常使用；说明使用用户语言；旧版本不被覆盖 |
| 3 | 使用成员 A 登录并开始记录炉次 | 只要求实验时间、合成方法和实验人；自动生成炉次编号；创建后进入同一炉次工作区 |
| 4 | 依次保存基本信息、目标产物、实验装置、前驱体、衬底、实验过程、异常与干预 | 每节可独立保存并回读；复合字段的数值和选项均保留；目标产物保存后，列表材料体系同步更新 |
| 5 | 在缺少锁定前必填字段时尝试“锁定工艺”，再补齐并重新锁定 | 首次失败按页面分组展示可理解的缺失项，炉次仍为“记录中”；补齐后直接进入“工艺已锁定”，不存在提交步骤 |
| 6 | 查看锁定后的炉次和样品 | 工艺区只读；每条衬底原子生成且只生成一个生长样，编号形如 `炉次编号-S01`；结果区仍可操作；重复刷新不重复建样 |
| 7 | 使用成员 B 登录，搜索并打开成员 A 的已锁定炉次 | 已锁定炉次对全组可见；成员 B 不能修改工艺，但可以操作样品结果 |
| 8 | 为自动生成的样品新增“直接观察” | 无需表征仪器；受控观察词显示正常；保存后结果待补提示自动消除，操作记录显示实际操作者 |
| 9 | 为同一样品新增“表征结果”，填写方法、仪器、条件和测量结果，并上传附件 | 一次保存形成完整组合结果；附件挂在对应结果下；详情页不暴露内部 ID 或 metadata JSON |
| 10 | 验证附件和结果冲突保护 | 有附件或关联测量结果时，删除表征记录应被阻止并给出下一步；按提示处理后可完成允许的操作；文件使用软删除 |
| 11 | 查看炉次操作记录 | 创建、分节保存、锁定、结果补录和附件操作均以用户可理解的动作、操作者和时间展示，不显示 payload 快照 |
| 12 | 返回炉次列表，按编号、材料体系、实验人、日期和状态分别筛选 | 筛选结果正确且只包含当前用户可见炉次；清除筛选可恢复列表 |
| 13 | 导出当前单炉次 JSON | 下载成功；包含完整嵌套工艺、样品、结果和附件元数据；不包含不可见数据 |
| 14 | 导出当前筛选结果 ZIP | ZIP 包含 `runs.csv`、`precursors.csv`、`substrates.csv`、`process_steps.csv`、`samples.csv`、`characterization_results.csv`、`files.csv`；关联编号可追溯，数组未塞入单个单元格 |
| 15 | 切换英文并抽查列表、炉次详情、表单、选项、帮助文本、状态、确认框和导出入口 | 页面不混用中文展示文案；切换语言不改变已经保存的 canonical 数据；PVD/PLD 不出现在可选合成方法或录入区 |
| 16 | 使用管理员解锁炉次 | 炉次回到“记录中”，工艺恢复可编辑；既有样品和结果证据链保持；操作记录新增解锁事件 |
| 17 | 全程检查浏览器控制台和网络请求 | 无 React 警告、未捕获异常、失败的业务外请求或意外 5xx；刻意触发且界面已正确处理的 4xx 单独记录，不判为控制台失败 |

## 4. 证据与报告

至少保留以下截图：炉次列表、分节保存、锁定失败缺失清单、锁定后自动样品、跨成员结果录入、操作记录、筛选结果、中英文页面。导出的 JSON 和 ZIP 只保存在临时验收目录，不提交仓库。

报告应包含：

- 环境与提交版本；
- 上表逐步的通过/失败、实际现象和证据路径；
- 发现的问题、严重度、复现步骤和修复结论；
- 控制台与网络异常清单；
- 最终结论：任一未修复的功能性问题均为 `FAIL`，否则为 `PASS`。
