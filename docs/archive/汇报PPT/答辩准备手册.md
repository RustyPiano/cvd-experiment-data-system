## 一、先讲清两个核心概念：字段字典 与 受控词表

很多人会混淆这两个词，开场你只要用一句话区分清楚，全场就稳了。

### 1. 字段字典（Field Dictionary）= "每个空格该填什么"的总说明书

- 它规定了整套记录里**一共有哪些字段、每个字段长什么样**。当前 = **10 个模块、68 个字段**。
- 每个字段都被明确定义了五件事：
  1. **键名**（机器用，如 `material_system`）+ **中英文名**（人看，如"材料体系 / Material System"）
  2. **数据类型**：文本、数字、日期、布尔（是/否）、下拉单选、多选、长文本，以及**数组**（一行行加，如多个前驱体）、**对象**（一组打包，如炉子信息）
  3. **单位**：如 ℃、sccm、rpm、mg、min、mm —— 单位写进字典，避免有人填"500"不知道是度还是分钟
  4. **是否必填**：必填字段在界面上标 **红色 `*`**，不填齐不让提交
  5. **是否挂受控词表**：挂了词表的字段就是下拉选择，不是手填
- **一句话定义**：字段字典就是这张"实验记录表"的**列定义规范**；它还能自动导出成 JSON Schema、字段字典文档，是这套"标准"对外可引用的产物。

### 2. 受控词表（Controlled Vocabulary）= "这一格只能从菜单里选"

- 有些字段不允许自由发挥，只能从一组**预设选项**里挑（下拉框）。当前 = **14 类受控词表**。
- **为什么要这么做**（这是被问到必答的点）：消除"同物异名"。比如衬底，有人写"硅片"、有人写"Si 片"、有人写"硅基底"——机器就认成三种东西，没法横向对比、没法统计。受控词表强制大家用同一个词，**数据才可比、可机读、可复用**。
- **字段字典与受控词表的关系**：字典里那一列标了"词表"的字段，它的候选值就来自对应的受控词表。两者是"规范"与"取值表"的配套关系。

### 3. 14 类受控词表的真实候选值（被问"都管了哪些"直接念）

| 词表 | 用在哪 | 候选值 |
|---|---|---|
| 材料体系 `material_system` | 基本信息 | MoS₂、WS₂、WSe₂、MoSe₂、hBN、graphene、其他 |
| 层数 `layer_count` | 基本信息 | 1、2、3、多层 |
| 样品环境 `sample_env` | 实验环境 | clean、normal、contaminated、unknown |
| 前驱体品牌 `precursor_brand` | 前驱体 | 阿拉丁、麦克林、国药、Sigma-Aldrich、Alfa Aesar |
| 制备方法 `precursor_method` | 前驱体 | 熔融、旋涂、粉末、溶液、其他 |
| 衬底品牌 `substrate_brand` | 衬底 | 华赫硅材料、合肥科晶、苏州研材微纳 |
| 衬底角色 `substrate_role` | 衬底 | top（上）、bottom（下）、control（对照）、product（产物） |
| 衬底类型 `substrate_type` | 衬底 | 硅片单抛 N<100>、蓝宝石各晶面（单抛/双抛 C/A/M 面）等 |
| 衬底尺寸 `substrate_size` | 衬底 | 5×5、5×8、5×10、10×10（mm） |
| 处理方法 `substrate_treatment_method` | 衬底 | 无、等离子清洗、UV 清洗、退火 |
| 气体标签 `gas_label` | 气体程序 | Ar、CO₂、O₂、Ar+H₂、Ar+O₂、H₂+CO₂、CO+Ar、air |
| 表征方法 `characterization_method` | 表征 | OM、Raman、PL、AFM、SEM、其他 |
| 质量标签 `quality_label` | 结果 | success、partial、failed、unknown |
| 失败模式 `failure_mode` | 结果 | 未生长、成核稀疏、覆盖率低、多层、不连续、均匀性差、相错误、非晶、污染、开裂、设备故障、其他 |

### 4. 词表怎么扩展（"不够用怎么办"的标准答案）

- **管理员**可在后台增删、停用、排序词表选项（API 已具备，前端管理界面尚未做，目前由管理员维护）。
- **品牌类**两个词表（前驱体品牌、衬底品牌）**对普通用户开放自助新增**：填写时遇到没有的品牌可直接录入，立即生效（系统标记来源为 user）。
- 多数"其他"情况：词表里带一个"其他"选项，再配合该模块的**备注/说明字段**写明具体内容。
- **注意**：目前**没有"申请—审批"流程**，新增即生效。被问到"会不会乱加"时这样答：品牌类放开是因为低风险；其余关键词表（材料/气体/表征等）只有管理员能动，保证规范性。

## 二、10 个模块逐个讲：填什么、怎么填

> 讲的时候不用逐字段念，抓住"每个模块对应实验的哪个动作 + 哪些是必填"即可。带 ★ 为必填。

**① 基本信息 basic_info（7 字段）** —— 这炉实验的"身份证"
操作人★、实验类型★、材料体系★（下拉）、实验日期★、实验目的、来源 Recipe、层数（下拉）。

**② 实验环境 environment（4 字段）** —— 当天环境本底
室内温度(℃)、室内湿度(%)、样品环境（下拉：clean/normal/…）、异常备注。

**③ 系统预检查 precheck（6 字段）** —— 开炉前的安全/洁净自检
密封完好、通风橱清洁、法兰口阻塞、舟污染、管污染（都是是/否勾选）、风险备注。
> 讲点：这一段就是把"老师傅开炉前默默检查的那几样"显式记录下来，失败复盘时能定位是不是预处理没做好。

**④ 前驱体准备 precursors（14 字段，含数组）** —— 用了什么源、怎么配的
这是个**列表**★：可以加多条前驱体，每条记录：物种、品牌（下拉）、浓度+单位、制备方法（下拉：熔融/旋涂/粉末/溶液）、以及随方法出现的参数（熔融温度、旋涂转速/时长、预旋涂转速/时长、制备时长、质量 mg、批次号）。
> 讲点：字段随"制备方法"动态出现——选了旋涂才需要填转速，体现"按工艺填，不堆无关字段"。

**⑤ 衬底处理 substrates（12 字段，含数组）** —— 基底是什么、怎么放、怎么处理
也是**列表**★，每条基底记录：角色（下拉 top/bottom/control/product）、类型（下拉，硅片/蓝宝石各晶面）、品牌（下拉）、尺寸（下拉）、批次、处理方法（下拉：无/等离子/UV/退火）、**相对温区位置**、处理温度/时长/功率/气体。
> 讲点：① "相对温区位置"是复现的关键背景信息，传统记录常漏；② 这里填的 top/bottom 基底会**自动生成样品**（见第三节）。

**⑥ 炉温程序 furnace_program（3 字段，含对象+数组）** —— 用哪台炉、怎么升温
炉子信息★（对象：选用的炉子）、前驱体放置（数组：源放在炉子哪个位置）、温区程序★（数组：每个温区一段升温/保温程序）。
> 讲点：温区程序是"分区、分段"的，记录每个温区的目标温度与升降温保温安排，这是复现"一炉"的核心。

**⑦ 气体程序 gas_program（8 字段，含数组）** —— 通什么气、何时通、多大流量
洗炉气体（下拉）、气体段列表★（数组：每一段记录 阶段、气体（下拉）、开始/结束时间(min)、流量(sccm)、混合组分）。
> 讲点：气体是"按时间分段"的程序，不是一个静态值——这正是结构化相对于"一句话描述"的优势。

**⑧ 过程观察 process_observation（3 字段）** —— 实验中肉眼/异常记录
颜色变化、异常事件（多选）、备注。边做边记。

**⑨ 样品表征 characterization（6 字段，含数组）** —— 测了什么、结果如何
表征方法列表★（数组：方法（下拉 OM/Raman/PL/AFM/SEM）、是否启用、激发波长(nm)、结果、备注）。原始数据/图片以**文件挂载**形式上传。
> 讲点：目前表征是"方法 + 结果文本 + 文件附件"，结构化提取是后续计划（对应不足页）。

**⑩ 结果分析 result_summary（5 字段）** —— 这炉成没成、为什么
结果摘要、质量标签（下拉 success/partial/failed/unknown）、下一步计划、**失败模式（多选，12 种预设）**、失败说明。
> 讲点：**失败也要结构化记录**——失败模式做成受控多选，未来能统计"我们组最常见的失败是哪几类"，直接支撑工艺优化。这一段呼应背景里"失败数据不可替代"的论点。

**贯穿全程：装置与方法**（不在 10 模块内，是强制关联实体）
每炉必须关联"装置示意图 + 标准化方法描述 + 参考文献/未发表说明"，缺一不能提交；同一装置方法建一次、之后引用。

## 三、样品管理页：是什么、怎么用、为什么有用

### 1. 样品（Sample）是什么
- 是**实验产出的"实物条目"**，归属于某一炉实验（一炉对多样品）。
- 每个样品有**全系统唯一编号**，自动生成，格式：`S-年份-序列号-角色[-字母号]`，例如 `S-26-0001-TOP`、`S-26-0001-PRODUCT-A`。

### 2. 样品从哪来（被问必答）
- **主要是自动生成**：你在"衬底处理"里填了 top/bottom 基底，系统自动建出对应的 top/bottom 样品；删了基底样品就软删除，重新加回来自动恢复。
- **可手动补充**：产物、对照样品（product/control）由用户在草稿态手动添加，编号自动续字母号（A、B…Z、AA…）。
- **克隆实验时**：会把源实验的样品一并复制并重新编号。
- 只有**草稿态**、且**本人或管理员**才能改样品；实验锁定后样品也随之冻结。

### 3. 两个页面分别能干嘛
- **样品列表页**（跨所有实验）：表格列有 样品编号 / 所属实验 / 材料体系 / 角色 / 基底类型 / 存放位置 / 更新时间；支持**按编号·实验号·材料体系搜索**、**按角色筛选**；点编号进详情，点实验号跳回那炉实验。
- **样品详情页**：显示身份信息（编号、角色、来源实验及其状态）；可编辑基底属性、**存放位置**、自由 JSON 元数据；下方汇总**该样品的所有表征文件**（文件名/方法/分类/大小/时间，可下载）。编辑同样 900ms 自动保存。

### 4. 它解决什么问题（价值，一句话讲）
- **追溯**：拿到一个表征结果/一片样品，立刻查到它来自哪炉实验、什么条件、放在哪。
- **检索汇总**：跨实验按材料体系/角色找样品，而不是一炉炉翻记录。
- **样品—文件归位**：表征文件直接挂到具体样品，不再散落。

## 四、实验记录的"一生"：填写 → 提交 → 修改 → 版本 → 锁定（含设计理由）

这是全场最容易被追问的部分，建议你把下面这条主线背下来。

### 状态机：草稿 → 提交 → 锁定，外加 作废
```
草稿 draft ──提交──▶ 提交 submitted ──确认锁定──▶ 锁定 locked
   ▲             │  ▲                         │
   └──退回草稿────┘  └────────管理员解锁─────────┘
              任意态 ──标记作废──▶ 作废 invalid（不删除）
   锁定 ──克隆──▶ 新草稿（血缘可查 + 继承字段标注）
```

### 1. 草稿态：边做边填，自动保存
- 编辑任一字段，**900ms 后自动保存**，且**按模块分段保存**（改了"气体"只存气体段），不怕丢、不怕卡。
- 必填字段标红 `*`；**校验不在草稿期拦你**，让你先把能填的填上。

### 2. 提交（submit）：完整性校验 + 生成第 1 个版本
- 点提交，后端跑**完整性校验**：必填字段齐了吗？装置/方法/参考文献关联了吗？不齐会逐条提示，补全才能提交。
- 提交成功 = 生成**版本 v1 的不可变快照**（整条记录的 JSON 存档），状态变为"提交"。
- **关键事实**：提交之后记录**仍然可以继续编辑**（直接改、自动保存照常）。提交≠不能改，提交只是"打了个存档点 + 通过了校验"。

### 3. 版本管理：快照怎么来、能看能回滚
- **版本不是每次自动保存都生成**，而是只在两个时刻生成：**①提交**、**②你显式"保存为新版本"**（可写变更说明）。这样版本列表是干净的里程碑，而不是几百条自动保存噪声。
- 每个版本存的是**整条记录的完整快照**（实验级字段 + 各模块 payload）。
- 能做：**查看版本列表、看某个历史版本详情、一键回滚（restore）到某版本**。回滚会把当前记录恢复成那个快照的样子（包括删掉快照里没有的模块），回滚本身不另生成版本，你可以继续改再存新版本。
- 老版本永远保留，不被覆盖——这是"可追溯"的底座。

### 4. 提交后怎么改（讲清两条路径）
- **路径 A（直接改）**：submitted 态可直接编辑、自动保存到当前工作副本；改完想留痕就"保存为新版本"（v2、v3…）。
- **路径 B（退回草稿）**：把记录 `退回草稿`（本人或管理员），回到 draft 重新整理后再提交。原有版本快照不受影响、仍可查可回滚。

### 5. 锁定（lock）：真正的"冻结"
- 锁定后**禁止一切编辑**（连样品都冻结），是数据归档的最终态。
- 锁定**同样要求通过完整性校验**；**本人可锁**；**只有管理员能解锁**（解锁是应急后门，解锁后退回到 submitted 可再改、改完再锁）。

### 6. 为什么把"提交"和"锁定"分成两步（设计意图，必背）
一句话：**提交 = "我做完了"（打存档点、过校验，但还能纠错）；锁定 = "确认无误，永久冻结防篡改"。**
- 中间留一个 submitted 窗口，让作者/审核者**复核、补版本、纠错**，避免一提交就锁死、发现笔误也改不动。
- 锁定后不可改 + 仅管理员可解锁 + 全程审计 → **防篡改、可追溯**。
- 这个两步结构也为将来的"提交—审核"审批流预留了位置。

### 7. 作废（invalidate）：失败不删、留痕
- 失败/异常实验**不删除**，标记为作废并注明原因，数据完整保留——直接对应背景里"失败数据不可替代"的主张。

### 8. 克隆 / 派生：做对照实验
- 可从 **submitted 或 locked** 的记录克隆出**新草稿**（已锁定的可被任何人克隆当模板，相当于"经过验证的配方"）。
- 新记录用 `derived_from` 记录**血缘**（来自哪炉），可追。
- 克隆时**自动继承工艺参数**，但**清空"本炉专属"的可变字段**（环境/预检查的备注、各表征的结果、结果摘要等），并在界面上标注哪些字段是"继承自源实验"，提醒你按本炉实际改。
- 说明：所谓"标注参数差异"是通过**继承标注 + 清空待填**实现的，不是自动算出一份 diff 文本。讲的时候说"系统会继承配方、标出继承项并清空需重填的字段"更准确。

### 9. 审计日志：每一步都留底
- 创建、更新、提交、存版本、回滚、锁定、解锁、退回、作废、克隆…**每个动作都记录"谁、何时、改前→改后"**。这是"可追溯、防篡改"在技术上的兑现。

## 五、怎么讲 + 高频问答（Q&A 预案）

**讲的节奏建议**：概念（字段字典/受控词表，2 句话）→ 10 模块即实验流程（流程图页）→ 两个重点（强制关联、生命周期状态机）→ 系统架构 → 现场点几下 → 不足与展望。演示别逐字段教学，重点点出"自动保存、提交校验、克隆继承、Excel 导入"四个动作。

**可能被问到的问题：**

- **Q：字段字典和受控词表有什么区别？**
  A：字典管"有哪些字段、什么类型/单位/必填"；词表管"某个字段只能从哪些选项里选"。前者是表结构规范，后者是取值规范。

- **Q：为什么非要用下拉、不让自由填？**
  A：消除同物异名，保证跨人跨批次可比、可机读；同时保留"其他+说明"和品牌类自助新增，不牺牲灵活性。

- **Q：填错了、提交后发现笔误怎么办？**
  A：提交态可直接改并存新版本，或退回草稿改；锁定前都能纠错，老版本还能回滚。

- **Q：锁定了还能改吗？**
  A：不能，锁定即冻结；确需更正由管理员解锁，全程留审计。

- **Q：版本是不是每次保存都存一个？会不会爆炸？**
  A：不是。自动保存只更新工作副本；版本只在"提交/手动存版本"时生成，是干净的里程碑。

- **Q：样品是手动建的吗？**
  A：基底 top/bottom 自动生成，产物/对照手动补；编号系统自动给、全局唯一。

- **Q：失败实验也要录入？图什么？**
  A：失败模式做成受控多选，可统计高频失败类型，直接服务工艺优化——这正是传统记录缺的。

- **Q：数据安全/会不会被人改了不认账？**
  A：状态机 + 锁定 + 全量审计（改前改后留底）+ 每日定时备份，多层保证。

- **Q：和通用电子记录本（如 OneNote/钉钉文档）有何区别？**
  A：那些是"自由文本容器"；本系统把 CVD 的工艺-表征拆成 68 个受控字段 + 强制关联 + 生命周期管控，产出的是结构化、可机读、可复现的数据，不是一段段描述。
