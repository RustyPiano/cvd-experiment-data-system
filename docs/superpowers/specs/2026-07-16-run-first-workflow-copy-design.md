# 炉次优先工作流与全量文案重构设计

日期：2026-07-16  
状态：用户已逐节确认

## 1. 背景与现状判断

当前后端的数据模型已经以炉次为最小记录单元，并具备字段单一源、装置与物料版本、状态守卫、样品、表征、附件和审计能力。主要问题不在底层骨架，而在用户工作流与界面表达：

- 前端同时突出炉次、样品和基础库，主线不明确。
- `v2`、`R0`、`cvd_v2`、`§1`、模块、实体、快照投影、锁版引用等实现或标准治理术语直接暴露给实验人员。
- `draft → submitted → locked` 中，成员可以自己提交后立即锁定，`submitted` 没有独立业务作用。
- 衬底记录与样品记录彼此独立，用户需要重复建立样品并选择抽象角色。
- 表征记录与实测产物分成两套表单，用户必须理解底层实体并手工关联。
- 缺少基础资料时必须离开炉次页面登记。
- PVD 仅为占位，却与已支持的 CVD 一起显示。
- 英文界面只翻译了部分 UI 外壳，字段和词表仍混有中文。
- 数据录入后缺少面向实验人员的检索和导出闭环。

本次设计保留已验证的底层能力，通过有针对性的状态、样品、结果、权限、导出和文案调整，把系统收敛为一个炉次优先的课题组实验记录工具。

## 2. 目标

1. 实验人员能从开始炉次一路完成工艺记录、锁定、样品生成、协作表征和数据导出。
2. 炉次是唯一主工作流；样品和基础资料是从属视图。
3. 支持边实验边记录，工艺分段保存，实验结束后锁定，结果后补。
4. 衬底记录自动产生样品，避免重复录入和关联歧义。
5. 表征过程与测得结果在一次用户操作中完成，底层仍保留规范化表结构。
6. 全部用户可见文案使用实验人员能直接理解的中英文，不暴露实现细节。
7. 导出结果适合 Excel、Python 和后续数据分析。

## 3. 非目标

- 不建设统计仪表盘或图表分析。
- 不在录入端判断实验成功或失败。
- 不开放 PVD 录入；后端兼容能力可以保留。
- 不增加复杂审批、项目组或逐炉次授权。
- 不实现实验模板、克隆和批量导入。
- 不擅自修改仍待专业对齐的观察现象、SEM 覆盖率、堆垛和外观描述词表语义。
- 不物理删除实验、样品或附件。
- 不重写现有数据层，也不为改文案重命名内部目录、组件或 API 路径。

## 4. 用户与产品心智模型

主要用户是二维材料课题组的实验人员。他们通常在实验开始时建立炉次，实验过程中逐段记录，实验结束后固定工艺信息，并在之后数天或数周内由本人或其他成员补录表征结果。

产品主线是：

`开始炉次 → 记录目标与装置 → 记录前驱体和衬底 → 记录实验过程 → 锁定工艺 → 补录样品结果 → 检索或导出`

系统服务于记录任务，界面应准确、克制、直接。标准治理和实现术语留在文档、后台校验与导出元数据中，不作为用户完成任务的前置知识。

## 5. 信息架构

### 5.1 主导航

1. **炉次记录 / Runs**：默认首页和主入口。
2. **样品 / Samples**：跨炉次查询已生成样品。
3. **基础资料 / Reference data**
   - 物料批次 / Material lots
   - 实验装置 / Experimental setups
   - 表征仪器 / Characterization instruments

不增加仪表盘。根路由继续进入炉次列表。

### 5.2 炉次工作区

新建炉次只要求实验时间、合成方法和实验人。编号由系统生成，实验人默认当前账号。创建后进入同一个炉次工作区，按以下顺序分节保存：

1. 基本信息 / Basic information
2. 目标产物 / Target material
3. 实验装置 / Experimental setup
4. 前驱体 / Precursors
5. 衬底 / Substrates
6. 实验过程 / Process
7. 异常与干预 / Incidents & interventions
8. 样品与结果 / Samples & results

界面不显示标准章节编号。内部模块键与现有 payload 结构继续保留。

## 6. 炉次状态

用户只看到三个状态：

- **记录中 / Recording**：工艺可编辑，可分节保存。
- **工艺已锁定 / Process locked**：工艺不可编辑，样品、表征和结果可继续补录。
- **已作废 / Voided**：误建、重复或无效记录，不可编辑。

状态流简化为：

`记录中 → 工艺已锁定`

- 删除 `submitted` 状态、提交端点、退回草稿端点及相关 UI。
- 创建者或管理员可以锁定记录中的炉次。
- 锁定前执行现有全量必填和最小可复现校验，但界面统一表述为“锁定前必填”，不显示 `R0`。
- 只有管理员可以解锁。
- 记录中的炉次可以作废；工艺已锁定的炉次不能直接作废。
- 实验失败或中断不是作废理由，应锁定并记录客观事件与结果。
- “结果待补 / Results pending”是提醒标记，不是炉次状态。
- 用户可明确标记“暂未表征 / Not characterized yet”；系统记录确认人和确认时间，并从待办列表移除，但仍在炉次上显示“暂未表征”。新增任何结果后自动清除该标记。
- 状态变化及原因继续写入审计。

## 7. 衬底与样品

### 7.1 自动生成

- 每条衬底记录带一个不展示给用户的稳定条目标识。
- 锁定工艺时，后端在同一事务中为每条衬底生成一个样品。
- 样品编号采用 `炉次编号-S01`、`炉次编号-S02` 的稳定格式。
- 重复锁定必须幂等，不得重复生成样品。
- 样品保存来源衬底标识和当时的衬底数据快照。
- 如果已有结果的来源衬底被删除，重新锁定必须拒绝并说明如何处理，不能静默断开证据链。

### 7.2 特殊样品

- 衬底生成的样品类型为“生长样 / Growth sample”。
- 用户可以从已有样品新增“派生样 / Derived sample”或“对照样 / Control sample”。
- 派生样必须保留父样品关系。
- 样品创建入口位于炉次结果区；样品列表只用于查询。
- 不向用户暴露 `metadata_json`，样品详情展示结构化来源与谱系。

## 8. 结果录入

### 8.1 用户操作

每个样品只有一个“新增结果 / Add result”入口，支持两种记录：

1. **直接观察 / Direct observation**：填写无生长、覆盖不连续、颗粒污染、衬底破损等客观现象，不要求仪器。
2. **表征结果 / Characterization result**：一次填写方法、仪器、测试条件、附件以及测得的物相、层数、覆盖率、畴尺寸和谱学指标。

同一样品可以有多条、不同方法的结果。原始文件和处理后文件挂在对应结果下。

### 8.2 底层实现边界

- 保留 `characterization_records` 和 `measured_products` 两张表。
- 增加组合读写 DTO 和事务型服务入口；前端不再分别操作两个技术实体。
- 直接观察只创建结果事实；表征结果在一个事务中创建或更新表征记录、测量结果和关联关系。
- 任一步失败时整次操作回滚，避免半成品。
- 删除有附件或被其他结果引用的记录时继续使用现有冲突保护。

## 9. 基础资料

- 物料批次、实验装置和表征仪器继续使用不可变版本行。
- 填写炉次或表征结果时优先选择已有资料。
- 选择器提供“新增资料”，在当前页面打开现有动态表单；保存成功后自动选中新记录。
- 实验装置是锁定工艺前必填；物料批次引用为推荐；表征仪器按实际情况选择。
- 成员可新增资料和追加版本，所有变化留审计。
- 旧版本不可覆盖，历史炉次继续保留当时引用的版本。
- 主页面副标题不解释版本机制；仅在更新确认和版本历史中使用普通语言说明“本炉次保留当前资料，后续更新不受影响”。

## 10. 权限与协作

### 10.1 成员

- 创建并编辑自己的记录中炉次。
- 查看全组工艺已锁定的炉次。
- 为任意已锁定炉次补录样品结果和附件。
- 维护共享基础资料。

### 10.2 管理员

- 查看和编辑全部记录中炉次。
- 解锁工艺。
- 处理误建记录。
- 维护共享基础资料。

### 10.3 可见性

- 记录中炉次仅创建者和管理员可见。
- 工艺已锁定炉次对全组可见。
- 已作废炉次仅创建者和管理员可见。
- 锁定工艺后，所有成员只读查看工艺；任意成员可以补结果，审计记录实际操作人。
- 不增加协作者名单、审批人或项目空间。

## 11. 文案体系

### 11.1 中文术语

| 禁用或替换的用户文案 | 统一文案 |
|---|---|
| v2 实验录入、v2 实验记录 | 炉次记录 |
| 新建实验 | 开始记录炉次 |
| 编辑实验 | 炉次详情 |
| 草稿 | 记录中 |
| 已锁定 | 工艺已锁定 |
| invalid | 已作废 |
| R0 | 锁定前必填 |
| 保存本模块 | 保存本节 |
| 基础库 | 基础资料 |
| 装置 | 实验装置 |
| 过程步 | 实验过程 |
| 过程事件 | 异常与干预 |
| 表征 · 实测产物 | 样品与结果 |
| 实测产物 | 测量结果 |
| 快照投影、锁版引用 | 本炉次保留当前资料，后续更新不受影响 |
| 元数据 JSON | 结构化样品信息 |

### 11.2 全量审查范围

审查并重写以下所有用户可见文字：

- 导航、标题、副标题、分节说明。
- 表单标签、帮助文本、占位符、单位和受控选项。
- 按钮、菜单、工具提示和无障碍标签。
- 空状态、加载状态、成功提示、错误提示。
- 只读提示、状态说明、缺失字段清单。
- 删除、作废、解锁、离开页面等确认对话框。
- 文件上传、下载和删除提示。
- 基础资料版本历史与更新说明。
- 导出入口及导出错误。

错误信息必须说明发生了什么以及用户下一步能做什么。按钮使用“动词 + 对象”，不使用孤立的“确认”“提交”“是/否”。

### 11.3 字段单一源

- 字段语义仍以 `docs/standard/field-source.yaml` 为唯一来源。
- 清理明确属于展示问题的标签、符号和伪单位，例如“样品/实验编号”、`▸` 前缀、“视性能”“见展开”“视仪器”以及中英夹注。
- 将非单位说明移入帮助文本或占位符，不把说明拼在标签后的单位位置。
- 对尚待专业确认的四组词表只改善排版和翻译，不改变分类粒度或科学含义。
- 所有字段修改必须重新生成后端模型、JSON Schema、前端字段元数据和 xlsx，并通过漂移校验。

## 12. 完整双语

- 中文 canonical 值继续作为 API 和数据库中的稳定值，不迁移现有科学数据。
- 现有 `label_en` 用于所有实验和基础资料字段；实验表单不得再固定读取中文标签。
- `field-source.yaml` 为受控选项增加按 canonical 值索引的英文显示名，生成器输出给前端。
- 前端按当前语言显示选项名称，但提交原 canonical 值，条件校验和历史数据保持不变。
- 对自由文本字段增加独立的中英文占位符，不再直接把 `options` 说明当占位符。
- 删除“视性能”“见展开”“视仪器”等伪单位；确有自然语言差异的帮助文本提供中英文版本。
- 中英文 locale 键、字段英文标签、词表英文显示名和生成物一致性由 CI 检查。

## 13. PVD

- 从用户可见的合成方法选项和录入表单中隐藏 PVD、PLD 及 PVD 专用区块。
- 不删除后端兼容代码和标准中的 PVD 定义，避免未来重新设计。
- 导出历史或 API 载荷时继续能够识别已有 PVD 值。
- 只有在定义 PVD 的最小必填集、校验和验收用例后，才重新开放界面。

## 14. 检索、审计与导出

### 14.1 检索

炉次列表支持按编号、材料体系、实验人、日期和状态筛选。筛选只返回当前用户可见记录。

### 14.2 操作记录

炉次详情提供只读操作记录，显示创建、分节保存、锁定、解锁、作废、结果补录和附件操作。展示操作者、时间和用户可理解的动作名称，不直接展示 payload 快照。

### 14.3 导出

- 单炉次导出完整嵌套 JSON。
- 批量导出当前筛选结果为 ZIP。
- ZIP 使用关系型多表 CSV：`runs.csv`、`precursors.csv`、`substrates.csv`、`process_steps.csv`、`samples.csv`、`characterization_results.csv`、`files.csv`。
- CSV 使用炉次编号、样品编号和结果编号关联，不把数组强行塞进单个单元格。
- `files.csv` 只包含附件元数据和下载地址，不默认打包大文件。
- 导出仅包含调用者可见数据。
- 使用 Python 标准库 `csv`、`json` 和 `zipfile`，不增加导出依赖。

## 15. 错误处理与一致性

- 锁定失败返回按页面分组的缺失字段，前端跳转或聚焦到对应分节。
- 分节保存失败保留本地输入并允许重试。
- 锁定与样品生成同一事务，失败时炉次保持记录中。
- 组合结果保存同一事务，失败时不留下孤立表征或测量结果。
- 就地新增基础资料失败时保持当前炉次输入和弹窗内容。
- 导出失败不影响任何业务数据，可安全重试。
- 所有权限失败使用 404/403 的既有可见性规则，不泄露不可见炉次。
- 所有写路径保留审计；文件继续软删除。

## 16. 实施边界

优先复用现有服务、动态表单、实体版本、审计、文件和字段生成管线。允许的最小结构变化包括：

- 炉次状态枚举移除 `submitted`。
- 炉次增加“暂未表征”的确认人和确认时间，用于区分未处理待办与已明确确认的无结果记录。
- 衬底条目的稳定内部标识和样品来源关联。
- 样品类型收敛为生长样、派生样和对照样。
- 事务型组合结果 DTO/服务/端点。
- 锁定炉次的跨成员结果写权限。
- 审计只读查询端点。
- JSON 与 CSV ZIP 导出端点。
- 字段元数据中的英文选项显示名和中英文帮助文本。

当前 v2 尚未生产切换，可更新单一 initial 与生成物，不新增无意义的增量迁移。批 8 前仍禁止执行 `deploy.sh`。

## 17. 验收与测试

### 17.1 后端

- 记录中炉次通过必填门后可直接锁定，不存在 `submitted` 路径。
- 锁定原子生成每条衬底对应的唯一样品，重复调用不重复生成。
- 成员可为他人已锁定炉次补结果，但不能修改其工艺。
- 直接观察和表征结果的组合写入满足事务性。
- PVD API 兼容保留，UI 不开放。
- 导出内容、行关联、可见性和 CSV 编码有自动化测试。
- 审计覆盖新增写路径。

### 17.2 前端

- 默认入口、导航顺序和所有主标题符合炉次优先模型。
- 用户可边实验边分节保存并锁定工艺。
- 衬底生成样品后，结果区按样品统一录入观察或表征结果。
- 缺少基础资料时可就地新增并自动选中。
- 中英文页面不混用语言；切换语言不改变提交的 canonical 值。
- 用户界面不出现禁用技术词；内部代码名和开发注释不在此限制内。
- 空态、错误、确认框和无障碍标签均有行为测试。

### 17.3 门禁

- 后端：`uv run ruff check . && uv run ruff format --check . && uv run pytest`
- 前端：`bun run lint && bun run typecheck && bun run test && bun run build`
- 字段源：重跑全部生成器与 `python3 docs/standard/check_field_source.py`
- 浏览器 E2E：开始炉次 → 分节保存 → 锁定 → 自动生成样品 → 其他成员补结果 → 导出。

## 18. 完成定义

成员无需理解版本代号、标准章节或数据库实体，即可完成一条炉次从开始记录到结果导出的完整生命周期；管理员可以安全解锁和追溯操作；中英文表达完整一致；字段科学语义、历史引用、审计和文件证据链不因工作流简化而丢失。
