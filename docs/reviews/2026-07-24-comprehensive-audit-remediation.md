# 全项目审查与整改报告（2026-07-24）

## 结论

本轮按“科学契约、数据完整性、权限与并发、导出可还原性、生产安全、用户工作流、双语与无障碍、文档一致性”八条线复核仓库，并修复全部可操作问题。生产环境未连接、未修改，未运行 `deploy.sh`。

当前仍保留的事项只有两类：

1. 需要课题组共同裁定的科学词表与命名问题，继续列在 `docs/standard/STATUS.md` 的“线 B”，不得由工程实现自行猜定；
2. 已明确延后的产品能力，例如实验模板、clone、PVD、分析仪表盘和批量导入，不属于现有功能缺陷。

## 审查边界

- 代码：FastAPI / SQLAlchemy / Alembic、React / TypeScript、部署与备份脚本、GitHub Actions。
- 数据：字段单一源、后端生成模型、JSON Schema、OpenAPI、前端字段元数据、字段字典和 xlsx。
- 工作流：实体版本、炉次草稿与锁定、自动样品、协作补结果、附件证据、审计、筛选和导出。
- 环境：SQLite 全套、真实 PostgreSQL 16 并发与约束测试、一次性本地浏览器环境。
- 非范围：批 8 生产切换；线上仍为旧部署，切换前禁止部署。

## 问题与整改矩阵

### A. 科学与字段契约

| 问题 | 风险 | 整改 |
|---|---|---|
| `structure_type` 的源定义允许多选，但业务与提示只按一个类型解释 | 同一产物可同时成为本征、掺杂和异质结，记录自相矛盾 | 字段单一源收敛为单选；删除前后端特判；DOM 测试验证类型切换、提示和组成明细同步 |
| 条件字段在判别字段尚未填写时可能被提前判为必填 | 锁定清单会列出页面上尚未显示的“组成明细”“数值”等字段，用户无法理解如何补齐 | 后端与前端共享语义统一为“驱动值缺失时条件不成立”；跨语言 fixture 覆盖 null、空串和空数组，真实浏览器复验缺失清单 |
| 复合对象以 `value` 为空就判整项缺失 | 合法的 option-only 随炉冷却无法锁定；恶意附加键又可能绕过实体校验 | `missing()` 改为仅在所有成员都为空时才判缺失；实体复合值先规范化再判断 |
| 掺杂剂接受 `0 at%` 或 `100 at%` | “零掺杂”仍标成掺杂，或失去基体语义 | 已填写的掺杂剂浓度强制 `0 < at% < 100`，生成模型、标准、帮助文本和测试同步 |
| 垂直异质结允许“上层层序早于下层” | 角色和堆垛顺序相互矛盾 | 所有下层层序必须小于所有上层层序，并加入无效组成用例 |
| 空间群只存 IT number，但没有兑现符号展示 | 用户难以核对 `194` 等编号，文案与产品能力不一致 | 保持权威存储为 `1–230`，界面自动显示 International short Hermann–Mauguin 符号 |
| 前端把 `domain_size_um = 0` 判为有效，后端与字段源要求严格正数 | 用户能点击保存，最后只收到 422；前后端科学边界漂移 | 前端数值解析和可保存条件统一使用 `> 0`，零值显示内联错误并禁止提交；DOM 回归覆盖零值与正值 |
| 数值、时间、压力、合金组成和混合气边界在不同载体上不完全一致 | SQLite/PG 或前后端出现不同接受范围 | 数值严格类型与上下界进入单一源并传播；APCVD/LPCVD 与绝对压力双向校验；事件使用带 offset 时间；合金唯一性、元素覆盖和浓度总和统一校验；气体使用数组 |
| sccm 参考温度曾允许绝对零度 | 物理边界不成立 | 改为严格大于 `-273.15 °C` |

### B. 数据完整性、并发与证据链

| 问题 | 风险 | 整改 |
|---|---|---|
| 三类实体版本只靠应用层约定不可变 | 绕过服务可直接更新或删除历史版本 | Alembic/模型统一增加 SQLite 与 PostgreSQL 不可变触发器，并在两种数据库验证 |
| 炉次锁定、工艺保存、附件绑定存在并发窗口 | 锁定后仍可能写入工艺；同一文件可能被两个不可变版本引用 | PostgreSQL 使用 `SELECT FOR UPDATE`；SQLite 使用同一行 no-op UPDATE 串行化并在等待后重检状态 |
| 实体附件绑定与删除未锁住文件行 | 两个版本引用同一文件，或版本引用已删除文件 | 绑定和删除共用文件仓储行锁；真实 PostgreSQL 双线程测试保证只有一个绑定成功 |
| 普通附件 note 无长度边界 | SQLite 接受、PostgreSQL 可能在 flush 时 500 | 两个附件入口统一 trim 与 500 字符上限，501 字符稳定返回 422 |
| legacy PATCH 接受 `attrs: null` | 通过请求模型后撞数据库 NOT NULL，返回 500 | 显式 null 在 API 边界返回 422；省略字段仍表示“不修改” |
| legacy `MeasuredProduct` PATCH 允许清空或改绑表征记录 | 表征指标可被改成没有仪器和条件来源的“直接观察”，证据类型自相矛盾 | 从 Update 契约和 OpenAPI 删除不可变外键；空值、同样品改绑和跨样品改绑均 422，正常指标更新保留原关联 |
| 结果、附件和删除之间的依赖保护不完整 | 可产生无文件证据或悬空结果 | 统一结果事务、附件软删除、删除冲突保护、状态待补刷新和审计均补齐 |

### C. 导出、检索与可还原性

| 问题 | 风险 | 整改 |
|---|---|---|
| 单炉次 JSON 的多次查询不在同一快照 | 并发新增结果时可能把表征结果误导出为直接观察 | 与批量导出共用 repeatable-read 快照；PostgreSQL 并发回归验证导出只见同一事务视图 |
| CSV 只展开部分嵌套值 | 仪器快照、结果属性或数组无法无损还原 | ZIP 保留权威 `records.json` 与 manifest；所有 nested leaves 递归关系化，并保留字段字典 |
| 筛选与导出可能使用不同可见性集合 | 页面看到的结果与下载数据不一致 | 列表、筛选和批量导出共用仓储可见性查询与分页口径 |
| 内部 canonical code 可能直接出现在界面 | 用户看到 `optical_microscopy` 等机器值，显得不专业 | 展示统一经过字段元数据与 i18n 选项映射，存储值不改写 |

### D. 安全、权限与生产运维

| 问题 | 风险 | 整改 |
|---|---|---|
| production 可带 debug、占位或短 JWT、占位邀请码启动 | 可预测凭据、调试信息泄露或错误开放注册 | production 启动即校验：debug 必须关闭、JWT 至少 32 字符且非占位、算法固定 HS256、邀请码为空或 8–128 字符非占位 |
| 管理员/用户 CLI 接受弱密码或空白身份字段 | 可创建不可用或弱口令账号 | email、姓名、密码在 CLI 边界统一长度与空白校验 |
| 备份和 schema guard 的数据库目标有生产样式默认值，可能与 Compose URL 指向不同库 | 备份与守卫通过，却在另一个未检查的库启动应用 | URL、容器、用户、库名均须显式且非占位；脚本逐项核对目标一致性，并把同一组已验证值传给备份与守卫 |
| inactive token 与读侧跨用户访问缺少完整回归 | 权限规则可能在只读接口漂移 | 增加 inactive、不可见资源 404、可见但无权 403、locked 协作结果例外的矩阵测试 |
| Pydantic 422 可能透出内部结构 | 用户看到实现细节，接口暴露过多 | 统一转换为稳定的 `detail.missing` / `detail.invalid` 结构并本地化 |
| 文件存储不可用或 tar 失败时备份仍可能“成功”，失败后还留下正式时间戳目录 | 部署后没有可恢复的文件备份；人工恢复时可能把半成品当成完整备份 | 数据库或文件任一备份失败即退出；退出 trap 只清理本次半成品，既有备份不动；部署脚本拒绝继续 |
| 自定义备份目录可通过符号链接绕过检查 | 在宽目录写标记并误删时间戳目录 | 先解析真实路径，再验证专用目录名/标记并拒绝根目录、仓库和 Git 目录 |
| 部署对未知或旧 schema 判断不足 | 生产容器迁移崩溃循环或误在非空库建表 | schema 状态、revision 和结构指纹均 fail-closed；批 8 前仍禁止执行 |
| SQLite 测试无法覆盖 PG 锁和触发器语义 | 本地绿但生产并发失效 | CI 增 PostgreSQL 16 真库 job，覆盖搜索索引、不可变触发器、快照导出和附件竞争 |

### E. 用户理解、双语与无障碍

| 问题 | 风险 | 整改 |
|---|---|---|
| 详情页可能把复合字段渲染为 JSON | 内行用户看到实现格式，难以核对物理量 | 复用结构字段定义，按具名子项、单位和本地化选项展示 |
| 查看历史版本时摘要仍写“当前版本” | 页面自身语义矛盾 | 历史状态改为“查看版本 / Viewing version”，当前版本标识只留给真实当前版本 |
| 英文结果页直接显示字段源中文单位“层” | 中英文混排，内行用户会认为本地化和字段契约未真正打通 | 结果表单与摘要复用统一单位本地化，英文显示 `layers`；DOM 测试同时覆盖表单和回读摘要 |
| 帮助、错误和控件关联不完整 | 键盘或读屏用户无法确定错误属于哪个字段 | 统一 `aria-describedby`、`aria-invalid`、必填标记、状态播报、跳至主内容和移动端导航 |
| 上传失败、未绑定文件和关闭表单的后果不清楚 | 产生孤儿上传或用户误以为已保存 | 上传中禁止关闭；保存时绑定到版本；取消/失败路径清理；已绑定文件只软删除 |
| 中英选项、状态和附件标签可能混用 canonical 值 | 英文界面残留中文或机器码 | 稳定 ASCII code 只用于存储；所有显示走双语资源；语言持久化并支持跨标签同步 |
| 查询失败可能被渲染成“空数据” | 用户误以为记录丢失 | loading / error / empty 状态分开，错误态提供重试并通过 live region 播报 |

## 明确保留的非缺陷事项

- `locked` 炉次锁住工艺，但允许全组成员补结果：这是经确认的协作规则，不是越权漏洞。
- 炉次不做物理删除、附件做软删除：这是审计与实验留痕规则。
- 复杂组合结构的化学式写法、观察现象粒度、SEM 覆盖率术语、堆垛类型粒度、外观词表仍需组内确认；现阶段以结构化 `components[]` 保存事实，不由代码猜测。
- 各气体分别绑定流量和纯度的成组数组、更多专用结构字段属于后续 schema 版本；当前限制已在标准与 manifest 中明示。
