## 1. 目标与基线

先关闭当前可达路径的缓存一致性、上传补偿反馈和静态资源行为问题，再清理已确认的结构债；保持制备字段、表征标准、状态机与既有数据含义不变。

- 本地基线：`304c96f` 加现有 alpha.44 未提交改动；生产为 alpha.43。实施前记录工作区差异，保留仪器预设等正在进行的修改，禁止整文件回退覆盖。
- 已通过基线：前端 60 个测试文件、438 个用例，默认并发 16.88 秒，typecheck/lint/build 全绿。这是复核时的证据，后续以实际工作区门禁为准。
- Python 使用 UV，JavaScript 使用 Bun；延续现有测试工具，不新增框架。
- 本计划不要求字段源、数据库迁移或 API 改名。若发现必须修改契约才能修复的问题，先记录具体差异并调整对应批次范围，不能用类型断言掩盖。

## 3. 批次 A：修复缓存一致性

### 实施

1. 扫描全部 `useQuery`、`setQueryData` 和 mutation 成功回调，整理实际读写关系，覆盖表征保存/作废、炉次状态切换、审核、未做表征确认/撤销。
2. 在 `status-logic.ts` 修正现有 `statusTransitionInvalidationKeys`，移除废弃 `v2-samples` 键，补齐样品与表征状态消费者。
3. 在 `simple-characterization-workspace.tsx` 与 `measurement-details.tsx` 对齐表征写入后的失效范围，同时更新受后端连带修改的炉次摘要、结果标记和审计。
4. 核对 `experiment-v2-edit-page.tsx` 审核和未做表征回调，补上对应的列表、详情和状态缓存。
5. 复用现有前缀及辅助函数。只有多个写入口确实共用同一集合时才提取小函数；不做全仓 QueryKey 重命名或工厂迁移，不以全局 `queryClient.clear()` 代替正确失效。

### 必须覆盖的消费者

| 数据 | 当前读取前缀 | 需要核对的写入动作 |
| --- | --- | --- |
| 样品列表/详情/按炉次样品 | `samples` | 炉次状态切换、表征保存/作废 |
| 按炉次及按样品测量列表 | `measurements` | 表征保存/作废；修订变化时核对历史/当前范围 |
| 表征列表、详情 | `characterizations`、`measurement-detail` | 表征保存/作废；按实际变更刷新详情 |
| 炉次编辑页/样品页炉次摘要 | `v2-experiment`、`experiments, detail` | 状态切换、审核、结果变化、未做表征确认/撤销 |
| 炉次列表 | `v2-experiment-list` | 状态切换、审核、结果变化、未做表征确认/撤销 |
| 表征入口及工作区状态 | `v2-experiment-status` | 状态切换、审核及其读取字段变化 |
| 审计/修订 | `v2-run-audit`、`v2-run-revisions` | 服务端实际写入审计或改变修订的动作 |

不同用户/token 后缀保留。优先使用能覆盖两种测量读取方式的 `measurements` 前缀；宽前缀失效是允许的，不以减少前缀宽度为本批目标。已失效但没有观察者的缓存允许在下次进入页面时重取。

### 验收

- 使用真实 QueryClient、显式 30 秒 staleTime 预置各页面缓存，触发实际成功回调或其共用函数；断言消费者失效或取得新数据，不能只断言返回某个字符串数组。
- 修正 `status-logic.test.ts` 中仅检查废弃键的测试；至少有一条失败回归能在修复前暴露问题。
- 浏览器本地验收：先访问样品详情 → 添加表征 → 30 秒内返回；先访问样品列表/表征入口 → 锁定炉次 → 立即返回；补有效结果及作废最后有效结果 → 返回炉次列表检查标记；审核后检查列表状态。无需手动刷新。
- 回归解锁、作废后的只读展示；后端拒写规则不变，不通过放开前端按钮解决状态问题。
- mutation 失败时不展示成功提示，不假造更新后的数据。

## 4. 批次 B：上传补偿反馈

### 实施

1. 追踪当前上传 → 创建表征 → 异常补偿流程，并检查已有附件组件的未保存文件管理/离开保护，能复用则复用。
2. 收集本次上传但尚未确认清理完成的文件 ID 和文件名，保留原始保存错误；在表单提供简短说明及安全的重试清理入口，沿用中英文 locale。
3. 重试清理前重新查询绑定状态：只有明确未绑定的文件才允许删除；已绑定文件视为需核对保存结果，查询失败保持未解决状态。404 等返回按现有 API 语义区分，不能将任意查询错误当作“已删除”。
4. 保存结果不确定时先刷新测量记录并核对关联，不能自动再次提交整笔表征；保留填写草稿及未解决清理信息，离开页面沿用现有未保存提醒。
5. 不引入后台清理服务，不承诺跨浏览器重启自动恢复；如果现有 API 无法判明绑定/保存结果，保留记录并明确提示核对，不盲删或盲重试。

### 验收

在已有工作区测试中覆盖：部分上传失败、创建失败且补偿成功、文件状态查询失败、删除失败后重试成功、创建已成功但响应丢失且文件已绑定。

要求：已绑定文件从不被删除；未解决的文件不会静默丢失；错误提示保留原始失败原因；成功路径保持一次提交及现有字段载荷。故障注入仅在本地测试环境进行。

## 5. 批次 C：静态资源与主题

### 静态资源

- 修改 `frontend-next/nginx/default.conf`，为 `/assets/` 设置独立 `try_files ... =404`，仅对实际存在的哈希静态资源设置一年 immutable 缓存，错误响应不得获得长期成功缓存。
- index/SPA HTML 使用可重新验证的缓存策略，`runtime-config.js` 保留 no-store，API 代理规则保持原语义。
- 生产 OpenResty 已提供 gzip；本批不为“启用 gzip”重复修改外层配置。
- 验收本地构建镜像的 nginx 配置检查及 HTTP 行为：真实 JS/CSS/font 类型正确；缺失 assets 返回 404；深层客户端路由返回 HTML；index/runtime-config 不被长期锁住；已有压缩在部署后仍有效。
- 长缓存不解决旧 hash 已删除的问题。发布验证应包含打开旧页面后部署新构建的导航场景，记录现有旧资源保留/重新加载机制的结果；发现 chunk 失败时不得宣称发布验收完成。

### Toaster

- `components/ui/sonner.tsx` 使用现有 ThemeProvider 的 resolvedTheme，保留调用方 props 覆盖行为与现有 CSS token，删除失真的单主题注释。
- 浏览器检查登录页和登录后页面的明/暗主题：成功、错误提示及关闭/焦点可见；主题切换后新增提示与当前主题一致。

## 6. 批次 D：结构与类型清理

按以下顺序执行，避免在旧代码上投入重构成本：

1. **清旧代码**：核对全部引用后删除废弃 ScientificMeasurementWorkspace 及仅由它使用的辅助逻辑；保留同文件仍在使用的制备代码、历史数据详情/导出能力。把列表页新版 lazy 变量名改为准确名称。删除不可达 dataset-query-page 及仅属于它的测试；保留重定向路由和共享 API。
2. **断真实循环**：更新调用方直接导入 SimpleTargetEditor，去掉 `simple-preparation-editors` 对它的回导出；不建立新的领域层。复查静态导入链并运行现有编辑器测试。
3. **恢复提交类型检查**：沿用生成的 MeasurementBundleCreate/属性类型，为构造对象和数组提供明确类型或 satisfies，消除现行工作区两处 `as unknown as`。校准条件/属性构造函数的返回类型；不得用 any、宽泛索引签名或另一处断言转移问题。旧组件删除同时消除其三处断言。
4. **清理依赖声明**：5 个 latest 固定为当前 bun.lock 实际解析版本；仅移动确属开发用途的依赖，删除 pnpm 残留。Bun 更新锁文件后审查差异，禁止顺带升级整棵依赖树；验证 frozen 安装及构建。是否调整 devtools 导入由生产产物证据决定。
5. **控制后续结构债**：复用已有 import/no-cycle 规则，先限定本次改动范围检查；不引入新检测依赖，不为通过规则做全仓迁移。

验收：无目标循环、无被删符号的有效引用；现行提交保留类型检查；制备/表征已有交互测试与载荷断言通过；清理前后页面能力一致。测试数因删除死页面测试可以减少，但必须明确对应关系，不能移除现行业务测试来恢复绿灯。

## 9. 2026-09-10 本地实施记录

### 已完成实现

- **A**：复用 status-logic，提供所有现行写入口共用的 invalidateRunQueries；状态切换、审核、未做表征确认、表征保存/作废覆盖样品、测量、炉次摘要、入口状态及审计/修订。删除废弃 v2-samples 失效键，保留会话键后缀。实际 QueryClient 测试覆盖消费者，并验证基础资料缓存不被清除。
- **B**：新增小型 recoverUploads 函数，逐个重新查询绑定状态；明确未绑定才删除，已绑定返回已有表征 ID，查询/删除失败保留文件名和 ID。表单展示重试/查看入口，未解决时禁用重复提交，保留原错误和草稿。无文件且保存响应不确定时要求先核对已有记录；明确的 4xx 拒绝（408 除外）允许修正后重试。清空草稿需要页面确认，不删除已保存记录。
- **C**：assets 独立 404，存在的哈希资源一年 immutable；SPA HTML 使用 no-cache，runtime-config 保留 no-store。Toaster 读取 resolvedTheme，保留 props 覆盖。
- **D**：删除旧表征工作区及仅由它使用的代码、不可达数据集页面及其两份测试；仍保留制备编辑器和历史详情/API。SimpleTargetEditor 直接导入，断开回导出循环。5 个 latest 按锁文件固定，devtools 调整至开发依赖，删除 pnpm 残留。现行生产源码不再含 as unknown as。

### 类型整改的实际调整

编译验证发现，生成的 MeasurementBundleCreate / PropertyValueWrite 含方法、属性编码、单位与条件字段的相关联合，动态字段循环不能仅靠类型注解得到可靠收窄。因此采用已有生成 JSON Schema 的独立校验代码：

- `scripts/generate-measurement-validator.ts` 读取 `docs/standard/generated/cvd-2d-process-v2.schema.json` 中 measurement_bundle；不维护新的手写 zod/字段规则副本。
- 将锁文件中已有的 Ajv 8.20.0 明确列为开发依赖，构建期生成并打包独立校验器；浏览器不引入 Ajv 编译器，也不动态求值 schema。
- 校验器返回类型守卫，实际校验通过后才调用强类型 createMeasurement。对象形状、方法/属性联合、单位及 schema 条件参与验证；UUID/date-time 格式仍由 API 验证，本地校验不替代后端或跨实体业务检查。
- 接入 gen:fields，现有 generated 目录漂移门禁覆盖新增产物；重复生成哈希一致。新增原语形状、未知方法、错误单位、缺少方法条件等回归测试。
- **已知代价**：独立校验 chunk 约 1,001 KB，gzip 75.36 KB，首次提交时按需加载；Vite 提示超过 500 KB 的未压缩 chunk。未提高阈值掩盖警告，也不声称本批缩小了所有构建产物。后续可在实测基础上优化生成器输出。
